# TS bugs found while porting

Format: `**B-N. Title.** file:line. What is wrong. Minimal repro. How Rust handles it.`

**B-1. `toMimeType` and `toMediaFormat` resolve `Object.prototype` keys.** `strands-ts/src/mime.ts` (`toMimeType`, `toMediaFormat`). Both index a plain object literal, so inherited keys match. Minimal repro: `toMimeType('constructor')` returns the `Object` function and `toMediaFormat('tostring')` returns `undefined` but `toMediaFormat('__proto__')` returns `Object.prototype`, not `undefined`. Rust matches on known strings and returns `None` (tested in `mime.rs`).

**B-2. Stream events and persisted blocks encode the same bytes differently.** `strands-ts/src/models/streaming.ts` (`ReasoningContentDelta.redactedContent: Uint8Array`) versus `src/types/messages.ts` (`ReasoningBlock.toJSON`). `JSON.stringify` of a stream event writes the `Uint8Array` as an index-keyed object (`{"0":0,"1":127}`), while the aggregated block writes base64. Minimal repro: `JSON.stringify(new ModelContentBlockDeltaEvent({ type: 'modelContentBlockDeltaEvent', delta: { type: 'reasoningContentDelta', redactedContent: new Uint8Array([1]) } }))` gives `{"0":1}` for `redactedContent`. Rust writes each form where TS does and reads both (P-16).

**B-3. `ModelContentBlockDeltaEvent.contentBlockIndex` is never set.** `strands-ts/src/models/streaming.ts` (`ModelContentBlockDeltaEvent`). The class declares `readonly contentBlockIndex?: number`, but the constructor ignores it and the data interface has no such field, so it is always `undefined`. Rust leaves it out (P-24).

**B-4. `InterruptStateData.interrupts` values are typed without `source`, but `toJSON()` writes one.** `strands-ts/src/interrupt.ts:126`. The declared persisted type and the written JSON disagree, so a typed consumer of `InterruptStateData` can't see `source`. Repro: `new InterruptState(...).toJSON()` in the conformance generator (`fixtures/interrupts/`). Rust: the crate-internal persisted struct includes `source` and round-trips it.

**B-5. `AgentResult.toJSON()` omits `interrupts`.** `strands-ts/src/types/agent.ts:627`. An interrupted run's `agentResultEvent` JSON carries no interrupt ids, so stream consumers must also read `interruptEvent`. Repro: `fixtures/agent/interrupt_tool.stream.json`. Rust: matches the TS JSON shape for wire parity; `AgentResult::interrupts()` stays available in-process.

**B-6. `SessionError` reaches users but isn't exported.** `strands-ts/src/errors.ts:208`, `src/index.ts:37-53`. Interrupt-state restore (`src/interrupt.ts:410-453`) and the session file storage throw `SessionError`, and `__tests__/interrupt.test.ts:369` asserts `toThrow(SessionError)`, but no barrel exports the class, so an application can only match it by `error.name === 'SessionError'`. Repro: restore an agent from a snapshot whose interrupt state has a malformed `pendingToolExecution`, then try `err instanceof SessionError` from `@strands-agents/sdk`. Rust: not ported with the exported classes (P-36); the item that ports interrupt restore decides how the error surfaces.

**B-7. `streamAggregated` keeps the tool state after unparsable tool input.** `strands-ts/src/models/model.ts:643-681`. When `JSON.parse(accumulatedToolInput)` throws, the catch records the error but `toolUseId`, `toolName` and `accumulatedToolInput` are never reset, so a following block that arrives without a start event is parsed as the same tool use again and dropped. Minimal repro: stream `toolUseStart`, `toolUseInputDelta '{bad'`, `contentBlockStop`, `textDelta 'after'`, `contentBlockStop`, `messageStop maxTokens`; the `MaxTokensError.partialMessage` lacks the `after` text block. Rust keeps the same behaviour (the stream fails either way, and a provider always sends block starts) and logs it here; see P-59.

**B-8. A Zod tool without a description can't be registered.** `strands-ts/src/tools/zod-tool.ts:77` defaults `description` to `''` (and `__tests__/zod-tool.test.ts:47` asserts it), but `ToolRegistry.add` throws `Tool description must be a non-empty string` for `''` (`strands-ts/src/registry/tool-registry.ts:146-149`), so `new Agent({ tools: [tool({ name: 'x', inputSchema, callback })] })` fails at construction although the description is documented as optional. Repro: `new ToolRegistry([tool({ name: 'x', inputSchema: z.object({}), callback: () => 'ok' })])` throws. Rust: `#[tool]` without a doc comment is a compile error (P-74); `FunctionTool` with `""` fails registration with the TS text.

**B-9. A hook-denied invocation's message skips `MessageAddedEvent`.** `strands-ts/src/agent/agent.ts:1300`. When a `BeforeInvocationEvent` hook sets `cancel`, `_streamInvocation` appends the denial message with `yield this._appendMessage(..)` straight to the caller, outside `_streamCore`, so `MessageAddedEvent` callbacks and the printer never see it, unlike every other appended message. Repro: `agent.addHook(BeforeInvocationEvent, e => { e.cancel = true })`, `agent.addHook(MessageAddedEvent, spy)`, `await agent.invoke('hi')`: `spy` is never called though `agent.messages` gains the message. Rust: fires `MessageAddedEvent` for it.
