# p11fixa staged decisions

**P-740. An invocation's own `AfterInvocationEvent` hooks are retried after a drop; extends P-98(2).** `Agent::after_invocation` records the run as abandoned (`AbandonedRun { state, repair: None }`) before it awaits the hooks and clears it when they return, so a call dropped inside them (a `timeout` or `select!` around `invoke` while a session save is in flight) leaves the run pending: the next `invoke`, `stream`, direct tool call or `shutdown()` runs every `AfterInvocationEvent` hook again from the first, with a cancelled signal, and `Drop for Agent` warns until then. A hook that had already returned runs twice, and the `resume` and continuations the retried hooks set are discarded, as for the deferred replay. No `AfterInvocation` stream event is emitted for the retry. Files: `agent/run.rs`.

**P-741. Per-agent skills are keyed by the agent's identity; reverses the id keying of P-383.** `AgentSkills` keeps `Vec<AgentEntry { owner: Weak<()>, id, skills }>` keyed on `AgentSandbox::owner()`, which `LocalAgent` and `ToolAgent` both expose, as `bash`, `mcp_router` and `ModelRouter` already do; an entry is dropped once its agent is gone (pruned whenever an agent's skills are loaded). `get_available_skills(agent_id: Option<&str>)` keeps its signature, because the caller holds an `Agent`, a `LocalAgent` or neither: it reads the live entry with that id, the one loaded last when several live agents share the id. The hooks and the `skills` tool never go through the id. Files: `vended_plugins/skills/agent_skills.rs`.

**P-742. `SessionManager::restore_snapshot` calls the target's own `load_snapshot`.** The sealed supertrait of `SnapshotTarget` gains `load_snapshot`, which `Agent` implements with `Agent::load_snapshot` (background-task guard, load, task table reload) and `LocalAgent` with its own; TS calls `target.loadSnapshot(snapshot)` (`session/session-manager.ts:272`). The restore at initialization still receives the `LocalAgent`, where the agent is not initialized and TS skips both steps too. Files: `session/session_manager.rs`.

**P-743. A direct tool call runs the deferred hooks first, and `load_snapshot` drops the deferred cancel-message event; extends P-91.** `ToolHandle::stream_with` awaits `finish_abandoned_run` before it resolves the tool (so also for an unknown tool name and with `record_direct_tool_call: false`) and yields its error as the stream's only item. `Agent::load_snapshot` clears the abandoned run's `repair` message when the snapshot carries `messages`: that history replaced the one the cancel message was appended to. The `AfterInvocationEvent` of the dropped run stays owed. Files: `agent/tool_caller.rs`, `agent/snapshot.rs`, `agent/run.rs`.

**P-744. `bash` `restart` stops a running command through a signal outside the session lock.** Each session carries a `tokio_util::sync::CancellationToken` next to its mutex (`SharedSession { session, stopped }`). `restart` replaces the entry and cancels the old token without locking; the running command drops its process and fails with `BashSessionError("Bash process exited unexpectedly with code unknown")`, the text TS produces when `stop()` kills the process (`onClose(null)`, `vended-tools/bash/bash.ts:117-121`). A call that was queued on the replaced session fails with the same error without starting a process, as its TS listeners would on the same `close`. An idle replaced session's process is killed when the session is dropped. `BashSession::stop` is removed (no caller). Files: `vended_tools/bash.rs`.

**P-745. A background tool run's tracer carries the agent's `trace_attributes`.** `BackgroundToolRun` gains `trace_attributes: Vec<(String, AttributeValue)>`, set on the run's `LocalTelemetry` before the `ToolTerminal` is built (TS `tracer: new Tracer(config?.traceAttributes)`, `agent/agent.ts:676`). The scheduler reads them once in `init_agent` from the agent's tracer (`LocalTracer::trace_attributes`, new crate-internal getter) and captures them in its execute closure, so `background_tasks::ToolRun` is unchanged: the attributes are fixed at construction, and reading them where the manager is built needs no field on every run. The regression test installs the crate's global test subscriber before its scoped recorder: in a filtered run where the scoped subscriber is the only one alive, a callsite first hit on another test's thread caches `Interest::never` (tracing-core's single-dispatcher fast path) and the spans are lost. Files: `tools/executors/executor.rs`, `background_tasks/background_tasks.rs`, `telemetry/tracer.rs`.
