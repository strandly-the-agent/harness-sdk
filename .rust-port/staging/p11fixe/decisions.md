**P-810. `ToolError::from_boxed` and `ToolError::downcast_ref`; the downcast rule gets one exception.** Review finding api-b1. A boxed error (`strands::error::BoxError`, `anyhow::Error`) is not a `std::error::Error`, so neither `?` nor the `#[tool]` return bound `E: Into<ToolError>` converts it, and a `From<BoxError>` impl is rejected by coherence beside the blanket `From<E: Error>`. Choice: `ToolError::from_boxed(error: impl Into<BoxError>) -> Self` keeps the error as the source, and `ToolError::downcast_ref::<E: std::error::Error + 'static>(&self) -> Option<&E>` reads a typed error back (`None` for an interrupt), so the caller of `FunctionTool::invoke` reaches the vended tools' typed errors without consuming the `ToolError`. `strands-rs/AGENTS.md` names `ToolError` and `Error::Other` as the exception to "the public API never requires downcasting": both carry an open set of user errors. No TS counterpart (TS throws any value). Alternative not taken: making the vended tools' error structs crate-private.

**P-817. `#[tools]`: cfg'd methods, `list = ".."`, reserved names; `#[tool]`: no panic for a name without a struct form.** Review findings correctness-b3, correctness-b4, api-b2, api-b3. (a) The generated tool struct, `<method>_tool` constructor and `tools()` entry of a `#[tool]` method carry the method's `#[cfg(..)]` attributes; `tools()` is built with one `push` per method. `#[cfg_attr(.., tool)]` is not recognized by `#[tools]` (the inner attribute must be written as `#[tool]`), and a `#[cfg_attr(.., cfg(..))]` on a method is not propagated. (b) `#[tools(list = "admin_tools")]` renames the generated list method, so a type can have several `#[tools]` blocks (invented argument name). (c) A `#[tool]` method named like the list method, and any method of the block named like a generated `<method>_tool`, are spanned errors. (d) A function whose name has no PascalCase identifier form (`_1`, `__`) gets "#[tool] can't derive a struct name from `..`: start the name with a letter" at the name. (e) `#[tool(context)] ctx: &mut ToolContext` gets "the `#[tool(context)]` parameter is `&ToolContext` or `ToolContext`".
