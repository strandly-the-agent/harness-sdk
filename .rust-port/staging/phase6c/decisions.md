**P-311. `ContextStrategy` shape.** TS `ContextStrategy` has `name`, optional sync `init(agent, stash?)` and async `apply(context)`. Choice: `#[async_trait] trait ContextStrategy: Send + Sync + 'static { fn name(&self) -> &str; fn init(self: Arc<Self>, agent: &mut LocalAgent, stash: Option<Stash>) {} async fn apply(&self, context: &mut ContextState<'_>) -> Result<bool>; }`; `init` takes `Arc<Self>` so eager strategies can register a `MessageAddedEvent` hook that holds themselves. Strategy state TS keeps in fields (`_stash`) sits behind a `Mutex`. The runner's TS `instanceof EmergencyTruncateStrategy` check compares `name()` with `EmergencyTruncateStrategy::NAME`, since the public API never downcasts. The offload strategies share crate-internal `OffloadBase` plus an `Offloader` trait (`base`, `removal_marker`, `replace_block`) in place of the TS abstract class; message identity (`indexOf`) becomes indices. TS reference: `context-manager/types.ts:21-36`, `strategies/offload/base.ts`. Files: `src/experimental/context_manager.rs`, `src/experimental/context_manager/strategies/offload/base.rs`.

**P-312. Agentic tools edit history through the tool batch.** TS `summarize_context`, `truncate_context` and `pin_context` splice `context.agent.messages` in place; Rust tools see `ToolAgent`, whose history is a snapshot (P-48). **P-316. Strategy-runner failures are logged.** TS `_runStrategies` counts the history outside its try, so a failing `countTokens` rejects the hook and fails the model call. Rust hooks can't return errors; the runner logs `context reduction failed` and the call proceeds (overflow recovery then reports no progress). Per-strategy failures are logged and skipped, as in TS. TS reference: `context-manager/context-manager.ts:205-244`. Files: `src/experimental/context_manager.rs`.
