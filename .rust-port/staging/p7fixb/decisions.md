**P-660. The routing option builders are re-exported next to their options (api-4).** `ModelRouterOptions` and `ClassifierStrategyOptions` live in private modules, so their `bon` builders could not be named downstream and had no rustdoc page. Choice: `strands::models::routing` re-exports `ModelRouterOptionsBuilder` with its state module `model_router_options_builder`, and `ClassifierStrategyOptionsBuilder` with `classifier_strategy_options_builder`, as Phase 3 did for `AgentBuilder`/`agent_builder`. New public names only; nothing renamed or removed. Test: `a_helper_can_take_and_return_the_routing_option_builders` in `strands/tests/model_routing.rs`.

**P-661. The classifier's routing context is written and measured as `JSON.stringify` writes it (parity-4, parity-9).** The user text sent to the classifier and the text measured against `max_candidate_chars` now come from `to_js_string` (JS number formatting: `1.0` is `1`, `1e21` is `1e+21`, `-0.0` is `0`), and the routing policy is tested for emptiness with `js_trim`. This changes model-facing bytes and the number in one error text toward TS only. The budgets still count characters, not UTF-16 code units (section 7.3 and the existing DIVERGENCES row `ClassifierStrategy` budgets), so the measured size equals TS's for text inside the Basic Multilingual Plane.
