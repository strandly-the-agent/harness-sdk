**P-283. A `bash` call owns its process; a closed pipe keeps the timeout armed.** Phase 8 review (correctness 1, 2): after `exec >&-` the call waited on `child.wait()` with no deadline and hung past its timeout, and a dropped call (a dropped `invoke`, which aborts the tool task) left its command running, so the next call read that command's output and sentinel as its own. TS keeps its timer armed until the process `close` event and can't drop a pending run. Choice: `run` takes the process out of the session for the call and puts it back only after both sentinels arrive. Any error, a timeout, or a dropped future drops the process, and `BashProcess::drop` kills the process group, so the next call starts a fresh session (as after a timeout). On EOF of either pipe, `run` races `wait()` against the same deadline: if bash exits first it is `Bash process exited unexpectedly with code <n>`, otherwise `Command timed out after <t> seconds`. Amends P-270. TS reference: `vended-tools/bash/bash.ts` (`run`). Files: `src/vended_tools/bash.rs`.

**P-284. Phase 8 public surface matches the TS barrels.** Phase 8 review (API 1-5). TS `vended-tools/*/index.ts` and `sandbox/index.ts` decide what is public. Choice: add `SLEEP_DESCRIPTION` (the 60-second text; TS exports it) and make `sleep_description` crate-internal (TS `sleepDescription` isn't exported); make the web_fetch `DEFAULT_MAX_BYTES`, `DEFAULT_MAX_CONTENT_CHARS`, `WEB_FETCH_DESCRIPTION_MARKDOWN`, `WEB_FETCH_DESCRIPTION_AGENTIC` and `DEFAULT_HANDOFF_TO_USER_DESCRIPTION` crate-internal (TS doesn't export them; the option docs state the defaults in words); re-export `generalist`, `GENERALIST_INSTRUCTIONS` and `GENERALIST_DESCRIPTION` from `strands::vended_tools` (TS exports `GENERALIST` from the barrel); make `sandbox::posix_shell` a private module, so `PosixShellSandbox`, `build_shell_env_prefix`, `validate_env_keys` and `shell_quote` have the one path `strands::sandbox::*`. Amends P-260, P-271, P-280, P-281. Files: `src/vended_tools.rs`, `src/vended_tools/{sleep, web_fetch, handoff_to_user}.rs`, `src/sandbox.rs`.

**P-285. `SandboxSource` converts from any `Sandbox`.** Phase 8 review (API 6): `.sandbox(..)` took only `Arc<dyn Sandbox>`, unlike `ModelSource` and `ToolSource`. Choice: add `impl<S: Sandbox> From<S>` and `impl<S: Sandbox> From<Arc<S>>` for `SandboxSource`, mirroring `ModelSource`, so `.sandbox(my_sandbox)`, `.sandbox(Arc::new(my_sandbox))`, `.sandbox(arc_dyn)` and `.sandbox(SandboxSource::Off)` all compile; the `strands::sandbox` module doc has a doctest for them. The `agent/config.rs` setter (`#[builder(into)]`) is unchanged. Amends P-260, P-265. Files: `src/sandbox.rs`.

**P-286. `http_request` keeps the last `set-cookie`.** Phase 8 review (parity 2): TS builds the response header record with `response.headers.forEach((value, key) => { record[key] = value })`; fetch `Headers` iteration joins repeated headers with `, ` but yields each `set-cookie` on its own, so the record keeps the last cookie. Choice: match TS. Repeated headers are joined with `, `, and a later `set-cookie` replaces the earlier one. Joining cookies with `, ` is not better (cookie values can contain commas, so the joined form can't be split reliably), and a list-valued field would change the output shape. Amends P-272. TS reference: `vended-tools/http-request/http-request.ts:64-66`. Files: `src/vended_tools/http_request.rs`.
