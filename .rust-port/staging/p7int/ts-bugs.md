**`CedarAuthorization` leaks a call count when the context enricher throws.** `strands-ts/src/vended-interventions/cedar/cedar.ts` `beforeToolCall` calls `_incrementCallCount` and then `this._contextEnricher(..)` inside the `isAuthorized` argument; an enricher that throws leaves the count incremented although the call was never evaluated, so with `onError: 'proceed'` or `'deny'` a rate-limit policy (`context.session.call_count < N`) is used up by failed calls. The deny and failure paths call `_decrementCallCount`; the throw path doesn't. Rust keeps the TS order and behaviour (P-415).

**The `HumanInTheLoop` approval prompt loses the classifier reason on resume.** `strands-ts/src/vended-interventions/hitl/hitl.ts` `_requiresApproval` returns `{ requiresHumanInTheLoop: true }` with no reason for a tool use id it has already classified, so when the agent resumes after an interrupt the `Confirm` prompt is rebuilt without ` — <reason>`. The interrupt id doesn't include the prompt, so the stored response still matches; only the prompt text differs between the first pass and the resume. Rust does the same.
