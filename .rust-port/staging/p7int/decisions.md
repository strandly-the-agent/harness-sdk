**P-411. **P-412. `on_error: throw` fails the event through a crate-internal channel; P-412 amends P-49.** P-49 made hook callbacks infallible. TS `onError: 'throw'` (the default) rethrows a handler's error out of the hook and the invocation, and the fail-closed default must not become a silent proceed. Options: cancel the event with a message (changes the outcome from an error to a tool result, and after-events have no cancel), or let SDK callbacks fail an event. Choice: the five gated events (`BeforeInvocationEvent`, `BeforeToolCallEvent`, `AfterToolCallEvent`, `BeforeModelCallEvent`, `AfterModelCallEvent`) carry a crate-internal `fail(Error)`; `HookRegistry::invoke` checks it after each callback and returns that error, skipping the remaining callbacks, as a throwing TS callback does. Public hook callbacks still return `()`. `on_error: deny` on an after-event logs TS's `deny has no effect` warning. An interrupt raised inside a handler (the handler calling `event.interrupt(..)`, or a `Confirm` without a response) stops the dispatch whatever `on_error` is: the registry compares the event's collected interrupts before and after each handler. The `hook_events!` invocation gains a `failure: take_failure` marker on those five lines, so the `strands-macros` UI snapshot `tests/ui/fail/sealed_slots.stderr`, which quotes the invocation, changes by one line. Files: `src/hooks/events.rs`, `src/hooks/registry.rs`, `src/interventions/registry.rs`, `strands-rs/strands-macros/tests/ui/fail/sealed_slots.stderr`.
