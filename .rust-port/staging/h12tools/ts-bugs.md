**The harness `edit` tool expands `$` patterns in `new_str`.** `harness-ts/src/tools/file-tools.ts:221` calls `content.replace(input.old_str, input.new_str)` with a string replacement, so `$&`, `` $` ``, `$'` and `$$` in `new_str` are replacement patterns: `new_str: "cost: $$5"` writes `cost: $5`, and `"$&"` writes back `old_str`. The tool describes `new_str` as "Replacement text." Rust writes `new_str` literally (P-850, `edit_inserts_the_replacement_literally`).

**The harness `edit` tool accepts an empty `old_str` on some files.** `file-tools.ts:213` counts occurrences with `content.split(input.old_str).length - 1`; for an empty `old_str` that is the file's UTF-16 length minus one, so a two-character file reports one occurrence and `new_str` is inserted at the start, an empty file reports -1 and takes the same path, a one-character file reports "did not appear verbatim", and a longer file reports "appears N times". Rust does the same.

**The harness `read` tool reads a negative `limit` as an end offset.** `file-tools.ts:141-142` passes `start + count` to `lines.slice`, and the schema is `z.number()` with no lower bound, so `limit: -1` returns every line but the last and `limit: 0` reports `[File has N lines; offset undefined is past the end.]`. Rust does the same.

**`web_fetch` can cut a surrogate pair.** `harness-ts/src/tools/web-fetch.ts:131` truncates with `text.slice(0, MAX_CHARS)`, which counts UTF-16 code units, so a page whose 50,000th unit is the first half of an astral character ends in a lone surrogate. Rust drops that character (a Rust string cannot hold half of one).
