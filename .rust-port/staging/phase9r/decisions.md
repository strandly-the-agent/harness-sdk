**P-251. `mcp_router` shape.** TS `makeMcpRouter(options)` returns an `InvokableTool` whose callback keeps per-agent `McpClient` maps. Choice: `strands::vended_tools::make_mcp_router(MakeMcpRouterOptions) -> Result<FunctionTool>` behind the `mcp` feature, re-exported with `MCP_ROUTER_DESCRIPTION` and `McpRouterToolError` (TS exports those three plus the `McpRouterInput` type). `MakeMcpRouterOptions { name, description, servers: IndexMap<String, McpServerConfig>, max_connections: Option<usize> }` (a config struct with `Default` and a `bon` builder, like the other vended tools). An empty `servers` and `max_connections: Some(0)` fail with the TS texts (``` `servers` must not be empty; ... ```, ``` `maxConnections` must be at least 1 ```); negative and fractional values are unrepresentable. `McpRouterInput` stays private: Rust tools take JSON input (`FunctionTool::invoke(JsonValue, ..)`), so a public input type would serve nothing; `DEFAULT_MAX_CONNECTIONS` stays private as in TS. The input schema is the `z.toJSONSchema` output of the TS zod schema (generated with the repo's zod 4.6.7, `$schema` removed) and is validated before the handler. Connections are keyed by the agent's identity token (`AgentSandbox::owner`, the token the `bash` sessions use, P-270) in a `Vec<(Weak<()>, BTreeMap<String, Connection>)>` behind a `std::sync::Mutex` held only for short sections, never across an await; cap and duplicate checks run after every await, as in TS. `list_connections` and the cap message sort ids through `BTreeMap` (byte order, which equals the TS UTF-16 sort except between supplementary characters and U+E000-U+FFFF). The listed-names cache (TS `WeakMap<McpClient, Set<string>>`) lives beside each connection. `call_tool` runs an ad-hoc `McpTool` built with `McpTool::from_server_tool` (empty description, `{"type":"object"}` schema) over the caller's `ToolContext` with the tool use renamed, so content mapping, errors and the cancel signal follow `McpTool`; an error result is rethrown as `McpRouterToolError` with its text lines joined by `\n` (non-text blocks as `JSON.stringify`), else `MCP tool returned an error`. `connect` failures propagate unchanged after the client is stopped, as TS rethrows. Empty-string `connection_id`, `server_name` and `tool_name` are treated as missing (TS `!value`). TS's `mcp_router requires an agent context` and `Unknown command` branches have no Rust counterpart (the context is always present and the command is an enum). Clients come from `McpClient::load_servers({name: config}, McpClientOptions::default(), McpLoadServersOptions::default())`; a crate-internal `make_mcp_router_with(options, ServerLoader)` seam replaces it in tests (the TS tests spy on `loadServers`). TS reference: `strands-ts/src/vended-tools/mcp-router/mcp-router.ts:13-303`, `types.ts:4-22`. Files: `src/vended_tools/mcp_router.rs`, `src/vended_tools.rs`.

**P-252. Closing a dropped agent's router connections.** TS registers each agent's connection map with a `FinalizationRegistry` and disconnects the clients in the background when the agent is collected (best effort). Rust has no finalizer on the agent's identity token. Options: a drop hook on the agent (none exists, and adding one reaches outside the router), a background reaper task (process-wide side effect), or pruning on use. Choice: every router call first removes the entries whose agent token is gone and awaits `disconnect` on their clients (errors logged at debug with the TS text and swallowed); the remaining clients close when the router is dropped, because dropping the last `McpClient` clone closes its transport. The debug line reads `connection_id=<..> | closing MCP connection of a dropped agent`. TS reference: `mcp-router.ts:93-97,156-169`. Files: `src/vended_tools/mcp_router.rs`.

**P-253. The MCP test server is shared with the router tests.** `strands::mcp::tests` and `strands::mcp::tests::server` (the in-process `rmcp` test server, `Gate`, `eventually`, `tool`) become `pub(crate)` under `#[cfg(test)]`, so `vended_tools::mcp_router::tests` reuses them instead of a second test server. Files: `src/mcp/mod.rs`, `src/mcp/tests.rs`.
