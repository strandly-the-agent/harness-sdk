# p11live: decisions to append to `.rust-port/DECISIONS-pending.md`

**P-560. `models/openai/mantle-routing.test.node.ts` has no Rust live test yet.** The TS spec lists every Mantle model (`GET /v1/models` with a minted bearer token) and probes each on `/v1` and `/openai/v1` to check `resolveMantleBasePath`; TS imports the resolver and the token setter through an internal path (`$/sdk/models/openai/mantle.js`), so they are not public API there either. The Rust counterparts `resolve_mantle_base_path`, `mantle_api_key_setter` and `create_token` are `pub(crate)`, so a test under `strands/tests/` can neither list the models nor mint the token, and a hardcoded model list would not test what the spec tests (new model families). Options: (1) an in-crate `#[ignore = "live bedrock"] live_*` test beside `mantle.rs`, which reaches `pub(crate)` and adds a test file and one `mod` line under `src/`; (2) a `#[doc(hidden)]` re-export for tests; (3) leave the row uncovered. Choice: (3) for this track, because its paths exclude `src/` except for a minimal bug fix; the Live checklist row says so, and (1) is the suggested follow-up for the lead. Partial evidence: `tests/mantle_live.rs` reaches `openai.gpt-oss-120b` and `openai.gpt-6.1-sol` in `us-east-1` through the resolved base path on the chat and responses surfaces. TS reference: `strands-ts/test/integ/models/openai/mantle-routing.test.node.ts:139-201`. Files: `strands-rs/strands/src/models/openai/mantle.rs:110,131,289`.

**P-561. Live tests reach `ConversationManager::reduce` and the summarize strategy through an invocation.** The TS specs call `manager.reduce({ agent, model, error })` and `strategy.apply({ messages, agent, utilization })` directly. In Rust the constructor of `ConversationManagerReduceOptions` is crate-internal (P-96) and `ContextState::new` needs the loop-side `&mut LocalAgent`, so code outside the crate cannot make those calls. Options: (1) expose constructors for tests; (2) drive the same code through `Agent::invoke`. Choice: (2), with a recording `Model` wrapper in `tests/live_context.rs`: it fails the first model call with `ContextWindowOverflowError` so the agent calls `reduce`, and a small `context_window_limit` makes the strategy run before the model call. Consequence: the exact message counts TS asserts right after a direct `reduce` (4 and 6) are replaced by checks on the reduced request (shorter than the overflowing one, tool use and result ids balanced, the summary first). TS reference: `strands-ts/test/integ/conversation-manager/summarizing-conversation-manager.test.ts:62-72`, `context-manager-summarize-tool-calls.test.ts:41-43`. Files: `strands-rs/strands/tests/live_context.rs`.
