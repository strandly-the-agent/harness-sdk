**P-233. **P-235. Connection sharing without an async lock.** TS shares one `_connectionPromise`; a waiter's abort signal only stops that waiter, the attempt keeps running, and the promise is released when it settles (`mcp/client.ts` `connect`). Choice: the attempt runs on its own spawned (instrumented) task, shared through `futures::future::Shared` stored in a `std::sync::Mutex` (held only to read or swap it; the task removes itself by id when it settles). Connection state lives in a `std::sync::Mutex<Conn>`; every RPC clones the `rmcp::Peer` out and awaits without a lock, so concurrent calls to one server run in parallel. A generation counter reproduces TS `_assertConnectionCurrent` (`MCP client disconnected`). `connect_with(reconnect, Option<&CancelSignal>)` is TS `connect(reconnect, { signal })`; the abort error is the cancel message or `The operation was aborted`. Files: `src/mcp/client.rs`.

**P-237. Request timeouts; no `TasksConfig`.** At the pin `requestTimeout` (and the deprecated `ttl`) exist only in `TasksConfig`, which belongs to MCP tasks (out of scope). **P-241. Legacy HTTP+SSE transport.** TS `loadServers` builds the MCP SDK `SSEClientTransport` for `transport: 'sse'` (`mcp/config.node.ts` `buildSseConfig`), and users can pass one as `transport`; `rmcp` 3.x has no SSE client (section 11, item 7). Choice: a crate-internal `SseClientTransport` on `rmcp`'s `Transport` trait (`src/mcp/sse.rs`), exposed as `McpTransport::sse(url, headers)`: a background task `GET`s the event stream (`Accept: text/event-stream`), the first `endpoint` event gives the `POST` url (resolved against the stream url; another origin fails with the SDK text `Endpoint origin does not match connection origin: <origin>`), `message` events feed the client, and each outgoing message is `POST`ed as JSON (`Error POSTing to endpoint (HTTP <status>): <body>` on failure, `SSE error: Non-200 status code (<status>)` for a failed stream). Headers go on the `GET` and every `POST`, as the SDK `requestInit` does. It parses events with `eventsource-stream`, which the `mcp` feature now enables. The protocol negotiation is the same Auto mode (P-236); a 2024-era SSE server rejects `server/discover`, so the client falls back to `initialize`. Files: `src/mcp/sse.rs`, `src/mcp/transport.rs`, `strands-rs/strands/Cargo.toml`.
