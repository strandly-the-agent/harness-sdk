**P-235. Connection sharing without an async lock.** TS shares one `_connectionPromise`; a waiter's abort signal only stops that waiter, the attempt keeps running, and the promise is released when it settles (`mcp/client.ts` `connect`). Choice: the attempt runs on its own spawned (instrumented) task, shared through `futures::future::Shared` stored in a `std::sync::Mutex` (held only to read or swap it; the task removes itself by id when it settles). Connection state lives in a `std::sync::Mutex<Conn>`; every RPC clones the `rmcp::Peer` out and awaits without a lock, so concurrent calls to one server run in parallel. A generation counter reproduces TS `_assertConnectionCurrent` (`MCP client disconnected`). `connect_with(reconnect, Option<&CancelSignal>)` is TS `connect(reconnect, { signal })`; the abort error is the cancel message or `The operation was aborted`. Files: `src/mcp/client.rs`.

**P-241. Legacy HTTP+SSE transport.** TS `loadServers` builds the MCP SDK `SSEClientTransport` for `transport: 'sse'` (`mcp/config.node.ts` `buildSseConfig`), and users can pass one as `transport`; `rmcp` 3.x has no SSE client (section 11, item 7). **P-244. Progress routing.** `rmcp` assigns a progress token to every request and reports all progress notifications to `ClientHandler::on_progress`; the TS SDK gives each call its own `onprogress`. **P-245.
