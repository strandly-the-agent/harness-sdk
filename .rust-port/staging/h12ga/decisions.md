# h12ga decisions (pending)

**P-1150. `SharedSource::into_arc` is public (SDK).** Context: review finding api-21; the harness options builder is to take a plugin the way `AgentBuilder::plugin` does (`impl Into<SharedSource<dyn Plugin>>`: a value, an `Arc` of one, an `Arc<dyn Plugin>`). `SharedSource` and its `From` impls are public, but the only way to take the `Arc` out was `pub(crate)`, and the harness cannot write the same three `From` impls for a type of its own (`impl<T: Plugin> From<T>` and `impl From<Arc<dyn Plugin>>` overlap outside the crate that owns `Plugin`). Options: (a) make `into_arc` public; (b) a harness setter that takes only `Arc<dyn Plugin>`, which leaves `.plugin(Todos::default())` not compiling. Choice: (a), one line, additive. Files: `strands-rs/strands/src/agent/config.rs`.

**P-1151. `HarnessAgentOptions::tools` and `plugins` are bon builder fields, declared first in the struct.** Context: review finding api-21, decision #32, section 11 item 42. bon setters can be called once, so "`.tools(..)` extends" needs `#[builder(field)]` members with hand-written methods, as `AgentConfig` has; bon requires such fields before the other members, so the two fields moved to the top of the struct (a struct literal is unaffected; `Debug` prints them first). The builder has `.tool(..)`, `.tools(..)`, `.plugin(..)` and `.plugins(..)`. `.plugins(..)` takes `impl IntoIterator<Item = impl Into<SharedSource<dyn Plugin>>>`, which is wider than the SDK's `plugins` (`Arc<dyn Plugin>` items only): `.plugins(vec![Todos::default()])` is the form the finding asks for, and a list of `Arc<dyn Plugin>` still compiles. One form that compiled before no longer does: `.tools(vec![read().into()])` (the old workaround) is now ambiguous, as it is on `Agent::builder()`; write `.tools(vec![read()])` or `ToolSource::from(..)`. Files: `harness-rs/strands-harness/src/agent.rs`.

**P-1152. A nested portable config type deserializes through the normalizer, under the path of its config key.** Context: review finding api-11; the nested types derived `Deserialize` with serde's rules and messages (`{"timeout": -5}` was accepted for `ProgrammaticToolCallerConfig`), while `HarnessAgentConfig` goes through `normalize_harness_agent_config`. Options: (a) drop `Deserialize` from the nested types; (b) implement it on each through the normalizer function for that type. Choice: (b): an existing test (`deserializes_the_nested_types_like_the_normalization`) shows reading a nested value alone is intended, and (b) keeps it with one validator. The impls are generated by one macro in `config/normalize.rs`; an issue is reported under the key's place in the config (`builtinTools.programmatic_tool_caller.timeout must be a positive number or null.`) with the `Invalid agent config:` header, the same text the whole config gives. Two texts have no TS counterpart because TS has no standalone schema: `must be an object.` for a non-object given to an object type, and `interventions must be a string or an array of strings.` for a standalone `null` (in the config, `null` is the absent value). `Setting<C>`, `HarnessConfigModel`, `HarnessModuleReference` and the name enums keep their derived `Deserialize` (not in the finding; `Setting<C>` delegates to `C`). Files: `harness-rs/strands-harness/src/config/normalize.rs`, `src/config.rs`, `src/types.rs`.

**P-1153. `ProgrammaticToolCallerConfig`: `timeout: Option<Option<Duration>>`, `allowed_tools: Option<Vec<String>>` (narrows P-934).** Context: review finding api-20, section 7.3 (`Duration`, not a float; `Option<T>` for unlimited). The struct is what a Rust caller writes in `BuiltinToolsConfig::programmatic_tool_caller`, and the typed path turned a negative or non-finite `f64` into a zero bound. Choice: `timeout` keeps the outer `Option` (absent is the 900 second default, `Some(None)` is no bound, as `MakeProgrammaticToolCallerOptions::timeout`); JSON stays a number of seconds, written as an integer when the bound is whole seconds (TS writes `60`, the `f64` field wrote `60.0`), read through the normalizer (P-1152), where a number past `Duration::MAX` is `Duration::MAX`. `allowed_tools` loses the inner `Option`: `null` and absent mean the same in TS (`harness-ts/src/builtin-tools.ts:175-177`) and in Rust. Cost: the normalized config no longer carries an explicit `allowedTools: null` (TS `config.test.ts:359-361` expects it kept); the ported case now asserts `{ "timeout": null }` for that input, and a `DIVERGENCES.md` row is staged. Either SDK reads the other's output the same way. If the lead wants the `null` kept on the wire, only the `allowed_tools` half needs reverting. `builtin_tools.rs` (`programmatic_tool_caller_options`) changed because the type did. Files: `harness-rs/strands-harness/src/config.rs`, `src/config/normalize.rs`, `src/builtin_tools.rs`.

**P-1154. The harness's builders live in one public module, `strands_harness::builders`.** Context: review finding api-2; `strands-rs/AGENTS.md` ("Builders") wants every public `bon` builder and its state module re-exported in each module-level `pub use` that names the config, and keeps builders off the crate root and the flat sets. The harness has no public module: its root is the flat set of the TS package's names. Options: (a) add the twenty builders and twenty state modules to the crate-root `pub use` lists; (b) one public module `builders` holding them. Choice: (b): it keeps the root equal to the TS export list (and the SDK rule that a flat set holds no builders), and gives rustdoc one page that lists every builder; `X::builder()` on each config links to it. The module is the crate's only public module. `harness-rs/AGENTS.md` should name it (the file belongs to track h12gc; not edited here). `MakeSubagentOptionsBuilder` gets a type-name-only `Debug`, written in `builders.rs` rather than with the SDK's `opaque_builder_debug!` (crate-private to `strands`). Files: `harness-rs/strands-harness/src/builders.rs`, `src/lib.rs`, `src/tools/mod.rs`, `src/plugins/mod.rs`.
