# Decisions (track p11misc)

**P-680. A context-preserving sub-agent restores its session before a resume is judged; the no-session warning needs no session.** Porting `resumes a context-preserving sub-agent with its own session manager after both are rebuilt` (`agent-as-tool.interrupt.test.ts:222`) failed: the rebuilt orchestrator got the "did NOT run" error result. TS `ChildAgentAdapter.restore` calls `child.initialize()` when the parent holds no stored turn, which loads the child's own session, and only then reads `_interruptState.activated`; Rust `restore` read `activated` on a child that wasn't initialized. Choice: `AgentAsTool::stream` initializes the child first when no turn is stored (an initialization error is logged with the TS text and takes the failed-restore path), and `restore` stays sync because the `subagent` tool always stores the turn. The warning `interrupted sub-agent has preserveContext=true and no session manager ...` is now logged only when the child has no session manager, as in TS (`agent-as-tool.ts:241`). `resumes after both agents are rebuilt from a session` now uses a `SessionManager` instead of `take_snapshot`/`load_snapshot`. Files: `strands/src/agent/agent_as_tool.rs`, `strands/src/agent/agent_as_tool/tests/interrupt.rs`.

**P-681. `Agent::as_tool` returns a `Result`; P-681 amends P-82.** TS `new AgentAsTool(..)` throws when the agent has a `SessionManager` and `preserveContext` is false (`agent-as-tool.ts:137`), and the three `sessionManager validation` cases of `agent-as-tool.test.ts` were a gap because Rust had no check at all: a context-resetting tool over an agent with a session manager was accepted silently. Choice: `Agent::as_tool(self, AgentAsToolOptions) -> Result<AgentAsTool>` fails with the TS text (`Error::other`). An agent passed in `.tools(..)` is wrapped by the infallible `From<Agent> for ToolSource`, so that path keeps the conflict in the `AgentAsTool` and `Agent::builder().build()` reports it (`ToolSource::into_tools` is fallible now), which is where TS throws for an agent in `tools`. Rejected: keeping `as_tool` infallible and failing at registration (an `AgentAsTool` handed over as a plain `Tool` loses its type, so the registry can't see the conflict) or at the first call (TS fails before any run). Every caller gains `?` or `.unwrap()`: the unit tests, `strands-macros/tests/downstream.rs`, `strands/tests/live_agent.rs`, the `AgentAsTool` doctest. Files: `strands/src/agent/agent_as_tool.rs`, `strands/src/tools/mod.rs`, `strands/src/agent/agent.rs`.

**P-682. The concurrent executor keeps a failed `ExecuteToolStage` chain to its tool call.** Porting `isolates unexpected middleware failures to the affected tool` (`agent.concurrent.test.ts:482`) showed that Rust failed the whole invocation when a tool middleware handler returned an error, under either executor. TS differs by executor: `ConcurrentToolExecutor` turns a generator failure into an error result for that call (`content: [error.message]`, `error` set, a `ToolResultEvent` and no `AfterToolCallEvent`; `concurrent.ts:85-108`), and `SequentialToolExecutor` rethrows (`sequential.ts:78`). Choice: `TaskMessage::Failed` carries the tool use id; `ConcurrentToolExecutor` maps it to the call's error result (`with_error` keeps the source), and the sequential executor still fails the batch. The Rust-only test `a_failing_handler_fails_the_invocation` now runs with `SequentialToolExecutor`, since the default executor no longer fails the invocation. Files: `strands/src/tools/executors/{executor,concurrent}.rs`, `strands/src/middleware/types.rs` (doc), `strands/src/agent/run/tests.rs`, `strands/src/agent/run/tests/middleware.rs`.

**P-683. Stale gap reasons of the parity sweep, part 2.** Every `the row:` entry of `test-title-map.json` (11) and every PARITY reason of the form "lands with Phase N" in the rows of this track is gone. Ported: the three `SessionManager` cases of `agent.stateful-model.test.ts`, the session-manager case of `agent-as-tool.interrupt.test.ts` (P-680), the three `sessionManager validation` cases of `agent-as-tool.test.ts` (P-681), seven cases of `agent.concurrent.test.ts` (default and supplied executor, three agent-cancel cases, middleware failure (P-682), interrupt telemetry), four cases of `index.test.ts`, and the `Offload` half of `stores its summary as text`. Now run as TS does: the delegation routing case (with `backgroundTasks`) and the token-usage integration cases (through `ContextManagerPreset::Agentic`). Reasons replaced because the case doesn't apply: the two consumer-break cases of `agent.concurrent.test.ts` (a dropped `AgentStream` aborts the tool tasks, so no `AfterToolsEvent` runs) and the cross-request case of `agent-delegation.test.ts` (hook callbacks return `()`). PARITY.md isn't edited here: the replacement rows are in `.rust-port/staging/p11misc/parity.md`, and the checker passes with them applied (`--parity`). Files: `strands-rs/docs/test-title-map.json`, the test modules named above.

**P-684. The crate root keeps the section 8.2 list; the TS root exports are checked by module path.** Of the 387 names `index.ts` exports, 253 resolve to a public Rust path by name, and the rest are out of v0.1, TS-only shapes, or renamed (`.rust-port/staging/p11misc/root-exports.md`). No root re-export was added. Open: `LifecycleObserver` has no Rust counterpart (P-413 deferred it to Phase 10, which didn't add it), and `SnapshotManifest`/`SnapshotLocation` are crate-private.
