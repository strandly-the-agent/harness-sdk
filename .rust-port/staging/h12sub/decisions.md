**P-890. The harness `AgentBuilder` is a boxed async closure.** `pub type AgentBuilder = Arc<dyn Fn(AgentSpec) -> BoxFuture<'static, Result<Agent, HarnessError>> + Send + Sync>` (TS `(spec) => Agent | Promise<Agent>`). A closure type rather than a trait because `builtin_tools` supplies one closure and tests supply closures; the spec is passed by value because the builder is its only reader. The name is the TS one; it does not clash with `strands::agent::AgentBuilder` because the harness never re-exports that.

**P-891. `strands::CancelSignal::abort_only` is public (SDK change, commit `feat(strands): make CancelSignal::abort_only public ...`).** TS `subagent.ts` passes the tool call's `cancelSignal` (an `AbortSignal`) to `child.stream`. In Rust the tool context's `CancelSignal` also carries the cancel message and the `after_current_tools` deferral, and the SDK's own `agent_as_tool` and vended `subagent` pass `abort_only()` so a child joins only the abort (P-97). The harness is a separate crate and could not call it, so the one-word visibility change is the smallest way to give the harness child the TS behaviour. Covered by `the_child_joins_the_parents_abort`.

**P-892. Shapes of the subagent axis types.** TS `Fixed`, `Inherit`, `Open`, `Choice`, `Option` are classes over `unknown`; the TS mode types are unions of them. Rust: `Fixed<T>(pub T)`, `Inherit` and `Open` are small public types, and each mode is an enum (`InstructionsMode::{Open, Choice(Choice<String>), Fixed(Option<String>)}`, `ToolsMode::{Inherit, Choice(Choice<String>), Fixed(Option<Vec<String>>)}`, `ModelMode::{Inherit, Choice(Choice<ModelSource>), Fixed(Option<ModelSource>)}`, `ContextAxis::{Fixed(ContextMode), Choice(Choice<ContextMode>)}`) with `From<Open>`, `From<Inherit>`, `From<Choice<_>>` and `From<Fixed<_>>` impls, so `Open.into()` and `Fixed(Some(..)).into()` read as in TS and `MakeSubagentOptions::builder()` setters take them directly. `Choice` and `ChoiceOption` (#71) are the SDK's own `strands::vended_tools::subagent::{Choice, ChoiceOption}` re-exported, not a second copy: same fields, `Choice::new`/`Choice::multiple`, `ChoiceOption::new(..).with_value(..).with_description(..)`. `McpServersMode` is a type alias of `ToolsMode` (the TS unions are identical). `PresetOptions` is a type alias of `Preset` (built with `Preset::builder()`), since a Rust struct with a builder is both. `GENERALIST` is a `LazyLock<Preset>` (a `Preset` holds a `String`, so it cannot be a `const`). Model values are `strands::agent::ModelSource` (TS `Model | ModelRouter | string`). `ContextMode` is an enum with `as_str()` and snake_case serde; `CONTEXT_MODES` is `[ContextMode; 3]`. `AgentSpec` and `Preset` carry `last_messages: Option<i64>`; `MakeSubagentOptions::max_depth` is `Option<u32>`, as `DEFAULT_SUBAGENT_MAX_DEPTH`.

**P-893. `make_subagent` returns `Result<Arc<dyn Tool>, HarnessError>`.** TS returns `Tool` and throws on a bad `tools` or `mcp_servers` `Choice`. The tool type stays private as in TS. `HarnessError` gains `SubagentToolsChoiceEmpty`, `SubagentToolsChoiceSingle`, `SubagentMcpServersChoiceEmpty`, `SubagentMcpServersChoiceSingle` and `UnknownAgentType { value, valid }`, each with the TS text as `Display`. A resolve or build failure reaches the model as the TS text `Subagent error: <message>`.

**P-894. `MakeSubagentOptions` has no `Default`.** `builder` is required, as in TS, so #65's `Default` cannot hold; the struct is exhaustive with public fields and a `bon` builder, and has a hand-written `Debug` that omits the closure.

**P-895. Child interrupts resume through the public result (section 11 item 47).** TS reads the private `child._interruptState` to decide whether a retained child resumes and which interrupts to answer. Rust keeps the interrupted child together with `AgentResult::interrupts()` in the pending map, keyed by tool-use id; a pending entry is by construction an interrupted child. Each child interrupt is raised on the parent through `ToolContext::interrupt` with the child's interrupt id as the name (TS does the same), so the parent-side id is `tool:<toolUseId>:<child interrupt id>`; on the re-run the stored responses go to the child as `InvokeArgs::InterruptResponses`. The tool ends with `ToolOutcome::Interrupt` for the first unanswered interrupt, which is what TS's throw does.

**P-896. The child runs as a request of its own.** TS harness `subagent.ts` calls `child.stream(prompt, { invocationState, cancelSignal })` and does not forward `invocationContext` (the SDK's `agent-as-tool.ts` and vended `subagent.ts` do). Rust follows the harness TS: `InvokeOptions { invocation_state, cancel_signal, .. }` only. See the ts-bugs entry. Progress events are every child `AgentStreamEvent`, serialized whole into `ToolStreamEvent::new` (item 46), including the final `agentResultEvent`, which TS also yields.

**P-897. JavaScript coercions of off-schema model input.** `resolveSpec` uses `String(x)` and `Number(x)` on raw model input. Rust implements both for JSON values in `subagent/resolve.rs` (`js_string`, `js_number`): strings, numbers, booleans, `null`, and arrays joined with `,` for `String`; an array or object is not a number for `Number` (TS `Number([5])` is 5), which is logged as a divergence row. A missing `task` is the string `undefined`, as in TS.

**P-898. One case of `subagent.test.ts` is not ported.** `surfaces an error when the child produces no result` drives a fake child whose `stream` returns nothing. A Rust `Agent` stream always ends with a result or an error, so the case cannot be built through the public API; the `Subagent produced no result.` branch is kept for a stream that ends without either.

**P-899. Test seam for the parent's messages.** `strands::testing::tool_context` gives a parent with no messages and the SDK has no public way to build a `ToolContext` over given messages, so the 13 context-sharing cases and `maps a label name to its value` call the two steps the tool itself runs (`Axes::resolve`, then `context::child_prompt`) with the parent's messages; `the_child_model_sees_the_parents_history_under_context_all` covers the same path end to end through a real parent agent. Children are real agents over `MockMessageModel`; the interrupt case runs a real parent and child and answers through `Agent::invoke(Vec<InterruptResponse>)`. No base-directory or env seam was needed.

**P-900. `async-stream` is a dependency of `strands-harness`.** Already in `[workspace.dependencies]` (the SDK uses it); the tool's stream is written with `async_stream::stream!` as the SDK's tools are.
