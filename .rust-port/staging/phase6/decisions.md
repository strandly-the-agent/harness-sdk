**P-300. Storage shape; P-300 adds to the P-15 name map.** TS `Storage` has four required methods and optional `namespace`/`search`, marks views with the `NAMESPACED` and `EPHEMERAL` symbols, and shares `normalizeKey`/`normalizePrefix`/`namespace`/`resolveNamespace` internally. Choice: `strands::storage::Storage` (`async_trait`, object-safe): `write(&str, &[u8])`, `read -> Option<Vec<u8>>`, `delete`, `list(prefix) -> Vec<String>`, provided `namespace(&self, prefix) -> Option<Result<Arc<dyn Storage>>>` and `search(&self, query) -> Option<Result<Vec<StorageSearchResult>>>` (`None` is the TS absent method), and `#[doc(hidden)]` `is_namespaced`/`is_ephemeral` for the two symbols. `InMemoryStorage` (cheap clone sharing an `Arc<Mutex<HashMap>>`) and `LocalFileStorage` get inherent `namespace(&self, prefix) -> Result<Self>` and `search(&self, query) -> Result<..>`, like TS's concrete return types, and `new`/`with_config(<Config>)` constructors (TS overloads; the positional overloads are dropped). `normalize_key`, `normalize_prefix` and the generic `namespace` view stay crate-internal as in TS (`@internal`, not exported from `storage/index.ts`). `SearchStrategy<S: ?Sized = dyn Storage>` keeps the TS generic with an optional `index`; `KeywordSearchStrategy` is a unit struct implementing it for every `S: Storage`, so `KeywordSearchStrategy.search(&storage, q)` reads like TS. `StorageSearchResult { key, score: f64, data: Option<Vec<u8>> }` is a `#[non_exhaustive]` struct with public fields (`new`, `with_data`); `score` is `f64` because vector backends return fractions. Listings sort by UTF-16 code units (JS `sort`). Tokenizing uses `regex` `[^\p{L}\p{N}_]+` (the TS pattern); `stripExtension`'s lookbehind is hand-written. `LocalFileStorage` uses `tokio::fs` on the host and the `Sandbox` file methods when sandboxed; `SandboxPathNotFoundError` (and an I/O `NotFound`/`NotADirectory` inside `Error::Other`) is a missing key. The scratch suffix uses UUID v7 (DIVERGENCES). `requiresHostFs` and the host-filesystem checks are not ported: the only such strategy (QMD) is out of v0.1. Name map: `Storage::is_namespaced`, `Storage::is_ephemeral`, `InMemoryStorage::with_config`, `LocalFileStorage::with_config`. TS reference: `storage/storage.ts`, `storage/in-memory-storage.ts`, `storage/local-file-storage.ts`, `storage/search/{keyword,types}.ts`. Files: `src/storage.rs`, `src/storage/{in_memory_storage,local_file_storage,search}.rs`, `src/storage/search/keyword.rs`.

**P-301. Session restore runs in `init_agent`; save failures are logged.** TS restores in an `InitializedEvent` hook and lets hook errors fail the invocation. Rust hook callbacks return `()` (P-49), so a restore error (corrupted JSON, a snapshot that doesn't load, missing storage) would be lost and the next save would overwrite the stored session. Options: restore in the hook and log; restore in the hook and skip later saves; restore in `Plugin::init_agent`. Choice: `init_agent` resolves the storage, restores, then installs the save hooks, so a failure fails `initialize`/`invoke` with the TS text, as in TS. It runs at the session manager's registration slot (after user plugins, before the model plugin), so every `InitializedEvent` hook sees the restored history (DIVERGENCES). Saves in the `MessageAddedEvent`, `AfterModelCallEvent` (redaction) and `AfterInvocationEvent` hooks log `session_id=<..>, error=<..> | failed to save the session snapshot` at error level (DIVERGENCES); the public `save_snapshot`/`restore_snapshot`/`list_snapshot_ids`/`delete_session` return errors. TS reference: `session/session-manager.ts` (`initAgent`, `_onAgentInitialized`). Files: `src/session/session_manager.rs`.

**P-302. Session errors and plain TS errors.** TS `SessionError` isn't exported at the pin (as P-92 notes) and `validation.ts` throws plain `Error`. Choice: follow P-23/P-92: `Error::Other` with the exact TS text. The adapter's `Failed to write '<key>' to storage`, `Failed to read '<key>' from storage` and `Corrupted JSON at '<key>'` wrap a private `SessionError` that keeps the storage or serde error as its `source()`. A snapshot file that parses as JSON but not as a `Snapshot` is also `Corrupted JSON` (TS casts without checking and fails later in `loadSnapshot`). TS reference: `session/snapshot-storage-adapter.ts` (`_readJSON`, `_writeJSON`), `session/validation.ts`. Files: `src/session/snapshot_storage_adapter.rs`, `src/session/validation.rs`.

**P-303. Session manager API; P-303 adds to the P-15 name map.** TS `SessionManager` is a class taking `SessionManagerConfig`, with `saveSnapshot({ target, isLatest })`, `restoreSnapshot({ target, snapshotId })`, `listSnapshotIds({ target, limit, startAfter })` and `deleteSession()`, where `target` is a `LocalAgent` (or a multi-agent orchestrator). Choice: `strands::session::SessionManager` (cheap clone around `Arc`; `new(SessionManagerConfig) -> Result<Self>` validates the id), implementing `Plugin` with the TS name `strands:session-manager` (`SessionManager::NAME`). `SessionManagerConfig { storage: Option<Arc<dyn Storage>>, session_id: Option<String>, save_latest_on: SaveLatestStrategy, snapshot_trigger: Option<SnapshotTriggerCallback> }` is a config struct; `SaveLatestStrategy` is a `#[non_exhaustive]` enum whose `Default` is `Invocation` (the TS default). `SnapshotTriggerCallback = Arc<dyn Fn(&SnapshotTriggerParams<'_>) -> bool + Send + Sync>` with `SnapshotTriggerParams { agent_data: &LocalAgent }`. Methods take `&impl SnapshotTarget`, a sealed trait implemented for `Agent` and `LocalAgent`, because `Agent` doesn't expose its `LocalAgent`; `list_snapshot_ids` takes `ListSnapshotIdsOptions { limit: Option<usize>, start_after: Option<String> }`. Immutable ids are `uuid::Uuid::now_v7()`. The adapter, `SnapshotLocation` and `SnapshotManifest` stay crate-internal (TS doesn't export the adapter; at the pin no SDK code writes the manifest, so `load_manifest`/`save_manifest`/`validate_scope` are used only by tests and carry `cfg_attr(not(test), expect(dead_code))`). Not ported: the deprecated `{ snapshot: SnapshotStorage }` storage form with `SnapshotStorage`/`SessionStorage`, `multiAgentSaveLatestOn` and `initMultiAgent` (multi-agent is out of v0.1), and the stash integration (`_includeStashData`, `_restoreStashData`, `_deleteStashData`), which lands with the context manager (Phase 6 item 3). Name map: `SnapshotTarget`, `ListSnapshotIdsOptions`, `SessionManager::NAME`. TS reference: `session/session-manager.ts`, `session/types.ts`. Files: `src/session.rs`, `src/session/session_manager.rs`.
