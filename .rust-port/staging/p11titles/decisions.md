**P-540. The test-title rule the checker enforces.** `strands-rs/docs/check-test-titles.mjs` checks every in-scope PARITY row: each TS `it(...)`/`test(...)` title needs a Rust test with its snake_case name in the files the row's second column names. The rule (script header and TESTING.md): drop `it.each` placeholders (`%s`, `$name`), drop apostrophes inside words, split camelCase words (`structuredOutput` is `structured_output`, `APIError` is `api_error`), lowercase, turn every run of characters outside `a-z0-9` into one `_`, trim `_`, and prefix `_` when the name would start with a digit. Names aren't truncated. The brief's plain rule (lowercase and replace only) matched 1,631 cases of the existing suite and this one 2,417, because the provider, conversation-manager, MCP and types tests were ported with split camelCase words and dropped placeholders; the forms that skip one of the first three steps are still accepted (middleware and background-task tests use the unsplit form), so no test of Phases 4-9 had to be renamed. Files: `strands-rs/docs/check-test-titles.mjs`, `strands-rs/docs/TESTING.md`.

**P-541. Repeated titles are matched through their `describe` titles.** A title that repeats in a spec is told apart by the innermost `describe` titles in front of it, either as enclosing `mod` names (`mod before_tools_event { fn creates_instance_with_correct_properties`) or as a name prefix (`model_message_event_creates_instance_with_correct_properties`); both existed in `hooks/events/tests.rs`. The checker matches the most specific names first over the whole spec, then bare names, each Rust test at most once. Files: `strands-rs/docs/check-test-titles.mjs`.

**P-542. `test-title-map.json` declares what the names can't.** `strands-rs/docs/test-title-map.json` maps `<spec path>` to `<ts title>` to a Rust test name (a merged or differently named test) or `{ "gap": "<reason>" }`. The key is the bare title, or the `describe` titles and the title joined with ` > ` when the bare title repeats in the spec; `"*"` covers every otherwise unmatched title of a spec. A row that ports nothing (`0/N`) and gives a reason needs no entries: all its cases count as gaps. The checker fails on a missing case, on `matched + declared` differing from the row's `ported`, on a case count differing from the row's `total`, on a map entry that matches no case and on a mapped Rust test that doesn't exist. Merged Rust tests were declared rather than split where the split would only duplicate set-up (the `AgentResult` `toString`/`toJSON` groups, the tool-name tables); a test whose TS title reads wrong without its placeholder keeps its Rust name and is declared (`sends_the_summary_text_to_a_model_without_server_side_summary`, the `'-' vs '_'` registry cases). Files: `strands-rs/docs/test-title-map.json`, `strands-rs/docs/check-test-titles.mjs`.
