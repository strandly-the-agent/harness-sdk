**P-1090. The harness live tests are an integration test, `tests/live_e2e.rs`, on the public API.** Context: the brief allowed a `#[cfg(test)]` module `src/live_tests.rs` if the crate-internal `Seams` base directory was needed. Options: (a) `src/live_tests.rs` with `Seams`; (b) `tests/live_e2e.rs` with an absolute `session.dir`. Choice: (b). `SessionConfig { dir: "<temp>/.agent/sessions" }` gives the same layout as the default `./.agent/sessions` of a process running in `<temp>` (`session_storage` splits the path into parent and namespace), memory takes an absolute `dir`, skills are off, and the model is given absolute paths; nothing needs the seam. `Seams` does not reach the sandbox either, so it would not have helped the environment plugin. Shared helpers are in `tests/live_support/mod.rs`. Files: `harness-rs/strands-harness/tests/live_e2e.rs`, `harness-rs/strands-harness/tests/live_support/mod.rs`.

**P-1091. `strands-harness` gets the dev-dependencies `aws-config` and `aws-credential-types`.** Context: a live test must skip with a message when AWS credentials are missing; on this host they come from the instance or container provider, so no environment variable shows whether they resolve.
