**P-720. `telemetry::get_tracer` and `telemetry::get_meter` (TS `getTracer`, `getMeter`).** Under `otel`, `get_tracer() -> opentelemetry::global::BoxedTracer` is `global::tracer(service_name)` and `get_meter() -> opentelemetry::metrics::Meter` is the global provider's meter scoped to the service name, the same scope the agent's own instruments use. Both are no-ops until a provider is registered, as in TS. A span started from `get_tracer()` inside an agent's `tracing` span parents under it once `setup_tracer` (or the application's own `tracing_layer`) is installed (the API review's `get_tracer_feasible.rs`). Files: `strands-rs/strands/src/telemetry/config/setup.rs`, `telemetry/mod.rs`. Review finding api-1.

**P-721. What the `setup_tracer` subscriber exports.** `tracing_layer` turns off the layer's own attributes (`with_location(false)`, `with_threads(false)`, `with_tracked_inactivity(false)`, `with_target(false)`), so an agent span carries only the attributes TS sets, on both the `setup_tracer` path and an application's own subscriber. The subscriber `setup_tracer` installs adds a per-layer filter, `metadata.is_span() && level <= INFO`: the agent's spans are `info_span!`, the `debug`/`trace` spans of dependencies (HTTP and AWS clients) are not exported, and `tracing` log lines don't become span events or set a span's error status, as TS `logger` calls never do. The SDK's own span events are unaffected (they go through `OpenTelemetrySpanExt::add_event`). An application that wants more builds its own subscriber with `tracing_layer`, which carries no filter. Files: `strands-rs/strands/src/telemetry/config/setup.rs`. Review finding api-2.

**P-722. `setup_tracer` with a custom provider leaves the global propagator alone.** TS returns right after `trace.setGlobalTracerProvider(customProvider)` (`telemetry/config.ts:191-199`) and documents that the caller owns the propagator setup; Rust now sets the W3C trace-context and baggage propagators only for a provider it builds. The global tracer provider and the `tracing` subscriber are still registered in both branches (the subscriber is what carries the agent's spans to the provider; it has no TS counterpart). This amends P-488. Files: `strands-rs/strands/src/telemetry/config/setup.rs`. Review finding api-3.

**P-723. `AgentBuilder::trace_attributes` and `baggage_attributes` take any iterator of pairs.** Both fields stay `indexmap::IndexMap` (insertion order is the export order), and the builder setters are `#[builder(default, with = FromIterator::from_iter)]`, so `.trace_attributes([("session.id".to_owned(), AttributeValue::from("abc"))])` compiles without an `indexmap` dependency and a map is still accepted. Callers that passed `[..].into()` or `.into_iter().collect()` pass the array. Files: `strands-rs/strands/src/agent/config.rs`. Review finding api-5.

**P-724. `DEFAULT_SERVICE_NAME` is private.** TS keeps it a module-private `const` (`telemetry/utils.ts:5`); nothing outside `telemetry/config.rs` used the Rust constant, so it is a private `const` there and `telemetry` no longer re-exports it. This amends P-482. Review finding api-8.

**P-725. `telemetry` re-exports the OpenTelemetry crates of its API.** Under `otel`: `pub use {opentelemetry, opentelemetry_sdk, tracing_opentelemetry, tracing_subscriber}`. `TracerConfig::provider`, the return types of `setup_tracer`, `setup_meter`, `get_tracer`, `get_meter` and `tracing_layer` and the `SpanProcessor` trait `BaggageSpanProcessor` implements come from these 0.x crates, so an application names them through `strands::telemetry::..` and always gets the versions `strands` resolved, as `mcp` and the provider modules do for theirs. Review finding api-4.

**P-726. The telemetry config builders are nameable, and `Exporters` has one.** `telemetry` re-exports `TracerConfigBuilder`, `MeterConfigBuilder`, `ExportersBuilder` and their state modules `tracer_config_builder`, `meter_config_builder`, `exporters_builder` (`state_mod(vis = "pub")`), so a downstream helper can take and return a builder, as with `AgentBuilder`/`agent_builder`. `Exporters` derives `bon::Builder` with `#[builder(default)]` fields (decision #65: public fields, `Default` and a builder): `Exporters::builder().otlp(true).build()`. Review finding api-6.
