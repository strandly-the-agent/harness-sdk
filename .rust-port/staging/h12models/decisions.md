**P-830. Harness model resolution takes and returns the SDK's `ModelSource`, and is synchronous.** TS `resolveModel(model: Model | ModelRouter | string | undefined, defaultModel, effort, webSearch, caching, cachingExplicit)` is async only because it imports providers dynamically. Choice: `pub(crate) fn resolve_model(model: Option<&ModelSource>, default_model: &str, options: ResolveModelOptions, env: &EnvLookup) -> Result<ModelSource>` with `ResolveModelOptions { effort, web_search, caching, caching_explicit }` (`Default`: auto, off, off, off); a string resolves to `ModelSource::Model`, an instance or router is cloned through. The public `supports_thinking` and `supports_web_search` take `Option<&ModelSource>` (`None` is the default model); `supports_media`, `resolve_web_fetch_model` and `EFFORT_LEVELS` are `pub(crate)`, as TS doesn't export them from the package entry.

**P-831. Provider table, and the texts for providers Rust doesn't build.** Rust v0.1 has `bedrock`, `bedrock-mantle`, `anthropic` and `openai` (#60). Choice: `google/`, `ollama/` and `litellm/` return `HarnessError::UnsupportedModelProvider` (`model provider "google" is not supported in Rust yet`, section 10); any other prefix returns `UnknownModelProvider` with the TS text, whose `Supported providers:` list names the four Rust providers (TS lists seven). A provider whose cargo feature is off returns `ModelFeatureDisabled` (`model '<spec>' requires the strands feature "<feature>"`) after the caching and effort checks, where TS would build the model; `bedrock-mantle` needs `openai` and `bedrock` and names the missing one (`openai` first). TS's "provider does not support prompt caching" branch is unreachable (only `ollama` lacks caching), so it has no variant.

**P-832. `supports_media` judges a model instance by its model id.** TS returns `false` for a `BedrockModel` instance whose id is in the `openai.` family and `true` for any other instance (`instanceof BedrockModel`). `strands::models::Model` has no downcast, and adding one is a public SDK change. Choice: an instance (and each router candidate, recursively) is judged by `Model::model_id()` read as a Bedrock id: `false` when its family starts with `openai.`, else `true`. The difference from TS is an `OpenAIModel` on Bedrock Mantle given as an instance with an `openai.*` id: TS answers `true`, Rust `false`, so `read` describes media in text for it unless `builtinTools.read.media` overrides. Pending: an SDK accessor would remove the difference.

**P-833. `Effort` is typed; the TS "not valid" text lives in `parse_effort`.** TS `resolveEffort` rejects a value outside `EFFORT_LEVELS` for untyped callers. Choice: `resolve_model` takes the `Effort` enum, and `pub(crate) fn parse_effort(name: &str) -> Result<Effort>` returns `HarnessError::InvalidEffort` with the TS text (`Effort "bogus" is not valid. Supported: auto, off, minimal, low, medium, high, xhigh, max.`) for the config normalization to call.

**P-834. Credentials, endpoints and regions go through the env seam into the SDK options.** TS providers read `process.env` themselves. Choice: the harness reads `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `AWS_REGION` and `AWS_DEFAULT_REGION` through `EnvLookup` and sets `api_key`, `client_config.base_url`, `BedrockModelOptions::region` and `BedrockMantleConfig::region`; an empty value counts as unset (TS `||`), and a value the lookup doesn't have is left to the SDK's own defaults. `resolve_web_fetch_model` reads the repointed-endpoint variables through the same lookup.

**P-835. `resolve_memory` shape.** TS `resolveMemory(options: ResolveMemoryOptions)` takes `stores?: MemoryStore | MemoryStore[]`, `model`, `dir`, `webFetch?: WebFetchConfig`, `writable`. Choice: `pub(crate) fn resolve_memory(options: ResolveMemoryOptions, env: &EnvLookup) -> Result<MemoryManager>` (synchronous) with `ResolveMemoryOptions { stores: Vec<Arc<dyn MemoryStore>>, model: Option<ModelSource>, dir: Option<String>, web_fetch_model: Option<ModelSource>, writable: bool }` and a `bon` builder (`writable` defaults to `true`). `web_fetch_model` is TS `webFetch?.model`, the only field TS reads, so the module doesn't depend on the `web_fetch` track's config type. The read-only view is the SDK's `strands::memory::read_only_view`. The default store is `LocalFileStorage::new(dir).with_namespace("")`, relative to the process working directory as in TS; `create_harness` passes a resolved directory.

**P-836. `HarnessError` variants for model resolution.** `ModelFeatureDisabled { spec, feature }`, `UnsupportedModelProvider { provider }`, `UnknownModelProvider { provider, spec, supported }`, `InvalidEffort { effort, supported }`, `UnsupportedEffort { effort, subject, detail }`, `CachingUnsupported { model }`, `NoWebFetchModel { provider }`; each `Display` is the TS (or section 10) text, with names quoted as `JSON.stringify` does.

**P-837. `regex` is a dependency of `strands-harness`.** It was already a workspace dependency. `CLAUDE_ID` is the TS expression with ASCII digit classes; its `(?!\d)` lookahead, which the `regex` crate doesn't have, is a trailing `(?:[^0-9]|$)`, which matches the same ids and captures the same groups under leftmost-first matching.

**P-838. `build_system_prompt(instructions: Option<&str>, context_parts: &[&str]) -> String`.** Empty instructions are skipped, as TS's truthiness check does.
