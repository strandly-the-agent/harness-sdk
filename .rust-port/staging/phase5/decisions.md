**P-150. Bedrock requests and responses go through their Converse JSON shape.** TS builds `ConverseStreamCommandInput` objects and maps plain JS event objects, and its tests assert on those objects. Options: format straight into `aws-sdk-bedrockruntime` builders and map typed SDK events, or build the Converse JSON shape (camelCase keys, `bytes` as base64, as on the Bedrock wire) and convert to and from SDK types at the transport boundary. Choice: the JSON shape. `format.rs` builds it, `parse.rs` maps events from it, and `wire.rs` converts it to SDK builders and SDK outputs back to it. The tests then assert with `json!` literals copied from the TS expectations. A crate-internal `Transport` trait (`send(Operation, JsonObject)`, `count_tokens`) is the offline seam; `SdkTransport` wraps the client. TS reference: `models/bedrock.ts:947-1065,1786-2094`. Files: `src/models/bedrock/{format,parse,wire,transport}.rs`.

**P-151. Bedrock config shape and the name map; P-151 adds to the P-15 name map.** `BedrockModelConfig` flattens the `BaseModelConfig` fields with the Bedrock ones (TS `extends`), with `merge` for `update_config`. `BedrockModelOptions { config, region, sdk_config, request_timeout, api_key }` stands for TS `BedrockModelOptions`; `sdk_config: aws_config::SdkConfig` is TS `clientConfig`; `request_timeout` is a `Duration`. `BedrockModel::new(impl Into<BedrockModelOptions>)` (a `BedrockModelConfig` converts), `BedrockModel::from_client(Client, BedrockModelConfig)`, inherent `config()`/`update_config(BedrockModelConfig)` beside the trait's `get_config`/`update_config(BaseModelConfig)`. Names TS lacks: `GuardrailTrace` (TS `'enabled' | 'disabled' | 'enabled_full'`), `GuardrailStreamProcessingMode` (`'sync' | 'async'`), `IncludeToolResultStatus::{Auto, Enabled(bool)}` (TS `'auto' | boolean`, same pattern as `CacheSection`). `BedrockCacheTtl`/`BedrockCacheConfig` are aliases of `CacheTtl`/`CacheConfig`. The client is created on first use (`tokio::sync::OnceCell`) so construction stays sync and offline, which also lets `ModelSource::Id` and the default model build a `BedrockModel` synchronously. TS reference: `models/bedrock.ts:186-406,483-528`. Files: `src/models/bedrock/{mod,client}.rs`.

**P-152. Region resolution and the env seam.** TS lets the AWS SDK resolve the region and wraps it to return `us-west-2` on "Region is missing". `aws-config`'s env override is test-util only. Choice: resolve explicitly: `region` option, the `sdk_config` region, `AWS_REGION`, `AWS_DEFAULT_REGION` (through a crate-internal `EnvLookup` seam), the shared config profile (`ProfileFileRegionProvider`), then `MODEL_DEFAULTS.bedrock.region`. IMDS is not consulted for the region (the JS SDK's Node default chain doesn't either). TS reference: `models/bedrock.ts:2454-2485`. Files: `src/models/bedrock/client.rs`.

**P-153. Bedrock error mapping.** TS maps only the in-stream `throttlingException` event to `ModelThrottledError`, rethrows every other AWS error as is, and maps any message matching the six overflow texts to `ContextWindowOverflowError`. Rust classifies `SdkError`s through the typed variants (a `TypedError` impl per operation error enum gives the exception name and message; never `Debug` text): `ThrottlingException` on the initial call or from `recv()` becomes `ModelThrottledError` (section 10: 429 maps to throttled), `DispatchFailure`/`TimeoutError` become `ModelNetworkError`, everything else becomes `ModelError` with the service message and the SDK error as source. The overflow check runs on every error the stream yields, as in TS. The exception name is kept internally for the structured-output fallback, the stale-thinking retry and `countTokens`. TS reference: `models/bedrock.ts:833-843,2076-2086`. Files: `src/models/bedrock/{transport,wire,mod}.rs`.

**P-154. `additionalArgs` keys.** TS spreads `additionalArgs` over the command input; the JS serializer silently drops keys that aren't request members. Rust applies the object over the request JSON (so known members, including `outputConfig`, `requestMetadata`, `promptVariables`, `performanceConfig` and `serviceTier`, take effect and override built ones) and fails the call with `key=<k> | additionalArgs key is not a Converse request field` for any other key (section 11 item 37). Files: `src/models/bedrock/wire.rs`.

**P-155. CountTokens skip set per model instance.** TS keeps `SKIP_COUNT_TOKENS_MODELS` process-wide with a static `clearCountTokensCache()`. Section 7.5 forbids that global state; like P-53 each `BedrockModel` owns its set, so there is no `clear_count_tokens_cache`. `ProviderTokenCountError` stays internal: TS throws and catches it inside `countTokens`, so Rust logs the same debug line and falls back. TS reference: `models/bedrock.ts:142-145,691-741`. Files: `src/models/bedrock/{mod,transport}.rs`.

**P-156. Cancellation ends the Bedrock stream.** TS passes the signal as `abortSignal`; its test expects the stream to end without an error and the producer to stop. Rust races the initial call and each `recv()` with `CancelSignal::cancelled()` and ends the stream (dropping the receiver closes the connection). TS reference: `models/bedrock.ts:776-781`, `__tests__/bedrock.test.ts:2167`. Files: `src/models/bedrock/transport.rs`.

**P-157. `Document` key order.** `Document::Object` is a `HashMap`. `SdkTransport` keeps a cache from a JSON value's text to the `Document` built for it in the previous request and reuses clones (a `HashMap` clone keeps iteration order, tested), so tool specs and history `toolUse` inputs serialize identically from call to call and cache prefixes stay stable within a process. The cache holds only the values of the last request. `Document` to JSON sorts object keys. Files: `src/models/bedrock/{document,wire}.rs`.

**P-158. Client user agent, timeout and API key.** User agent: TS appends `strands-agents-ts-sdk` to `clientConfig.customUserAgent`; `AppName` can't hold a space, so Rust sets app name `strands-agents-rust-sdk` unless `sdk_config` already has one, which is kept. Timeout: `request_timeout` (default 120 s) becomes the SDK read timeout, over the read timeout of `sdk_config`; other timeouts in `sdk_config` are kept. TS's two handler-instance cases have no Rust analog. API key: the SDK config loses its SigV4 credentials provider and gets `bearer_token`, so requests authenticate with the key (the TS middleware sets `Authorization: Bearer`). `AWS_BEARER_TOKEN_BEDROCK` keeps working through the SDK. Not verified live (no API key in this environment). TS reference: `models/bedrock.ts:508-526,2373-2441`. Files: `src/models/bedrock/client.rs`.

**P-159. Guardrail trace JSON.** TS passes the SDK trace object through on `modelMetadataEvent.trace` and searches it for `action: BLOCKED` with `detected: true`. The Rust SDK's trace types have no serde without `aws_sdk_unstable`, so `wire.rs` writes the JSON by hand: `modelOutput`, `inputAssessment`, `outputAssessments` and `actionReason`, with the topic, content, word, sensitive-information and contextual-grounding policies, `invocationMetrics.guardrailProcessingLatency`, `appliedGuardrailDetails` ids, and `promptRouter.invokedModelId`. Automated-reasoning findings and the invocation usage and coverage are left out (they carry no `action`/`detected`, so blocked detection is unaffected). Files: `src/models/bedrock/wire.rs`.

**P-160. Shared model-code edits and placement.** `models/model.rs` `estimate_tokens_heuristic` is now `pub(crate)` so the Bedrock `count_tokens` override can fall back to the TS heuristic (TS calls `super.countTokens`). `thinking-binding.ts` is ported as `models/bedrock/thinking_binding.rs` (crate-internal) because only Bedrock uses it so far; the Anthropic provider can move it to `models/`. TS `NOOP_TOOL_SPEC` lives in `models/bedrock/format.rs` as `noop_tool_spec()`. Files: `src/models/model.rs`, `src/models/bedrock/`.
