# Pending decisions from Phase 5 items 3 and 4 (`OpenAIModel`, Bedrock Mantle)

Format as in `.rust-port/DECISIONS-pending.md`; the lead folds these in.

**P-200. OpenAI module, names and options; P-200 adds to the P-15 name map.** TS `models/openai/` exports `OpenAIModel`, `OpenAIApi`, `OpenAIChatConfig`, `OpenAIResponsesConfig`, `OpenAIModelConfig`, `OpenAIModelOptions` (a union discriminated on `api`) and `BedrockMantleConfig`. Choice: `strands::models::openai` behind the `openai` feature with `OpenAIModel`, `OpenAIApi { Responses (default), Chat }` (with `as_str`), one flat `OpenAIModelConfig` (the six base fields plus `params`, `cache_config`, `frequency_penalty`, `presence_penalty`, `stateful`, with `merge`) instead of the two api-specific configs (TS `getConfig` already returns the merged view), and `OpenAIModelOptions { api, api_key, client_config, config }`. New names: `OpenAIClientConfig { base_url, api_key, organization, project, default_headers, max_retries, timeout }` (the subset of the vendor `ClientOptions` the Rust client honours), `OpenAIApiKey` (TS `string | ApiKeySetter`: `new`, `from_setter`, `From<&str>`/`From<String>`, redacted `Debug`) and `ApiKeySetter` (TS name, an `Arc<dyn Fn() -> BoxFuture<Result<String, BoxError>>>`). The TS `client` option (a pre-built vendor client) has no Rust equivalent; a crate-internal `OpenAIClient` trait is the transport seam tests replace (`Transport::Injected`, which skips the key check as TS does with `client`). Fields that only one API reads are ignored by the other, as at TS runtime (TS rejects them at the type level only); this is documented on the struct. `update_config(OpenAIModelConfig)` returns `()` (nothing in it can fail). Error texts name Rust fields where TS names camelCase options (`'api_key' option (string or function)`), as P-180 did for Anthropic. TS reference: `models/openai/types.ts`, `model.ts:90-140`. Files: `src/models/openai.rs`.

**P-201. OpenAI transport: own copy of the vendor-style client.** The `openai` package's transport (6.45.0, `client.js`) retries like the Anthropic one: `maxRetries` 2, 408/409/429/5xx and `x-should-retry`, 0.5-8 s backoff with up to 25 % jitter, ten-minute timeout. Differences from the Anthropic port that follow the vendor code: errors take `message` and `code` from the body's nested `error` object (`APIError.generate`/`makeMessage`; a JSON body without `error` words as `<status> status code (no body)`), only a string `code` is kept (numeric and `null` codes from compatible servers are dropped, which is what TS `classifyOpenAIError`'s `typeof` guard does), `retry-after-ms`/`retry-after` are honoured as given with no 60 s cap (a negative, `NaN` or over-`2^31-1` value waits 1 ms, as Node's `setTimeout`), `[DONE]` ends the stream, a data object with a truthy `error` fails it (`APIError(undefined, data.error)`), an `apiKey` setter runs before every attempt with the vendor error texts, and `Authorization: Bearer`, `Accept: application/json`, `OpenAI-Organization`/`OpenAI-Project` are sent. Env defaults read through the env seam: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_ORG_ID`, `OPENAI_PROJECT_ID`, `OPENAI_CUSTOM_HEADERS` (all trimmed; `OPENAI_ADMIN_KEY`, `OPENAI_WEBHOOK_SECRET` and `OPENAI_LOG` are not read: the admin key only authenticates admin endpoints, the other two don't affect model calls). Options: share one transport module with Anthropic (touches the committed Anthropic code and both features), or a second copy under `models/openai/`. Choice: the copy, to keep this item's edits inside `models/openai*`; the shared parts (`parse_js_float`, backoff, `should_retry`, header merge) can be folded into one crate-internal module at the Phase 5 review. `X-Stainless-*` and `User-Agent` headers are not sent (as in the Anthropic port). TS reference: `node_modules/openai/client.js:140-200,440-620`, `core/error.js`, `core/streaming.js`. Files: `src/models/openai/client.rs`.

**P-202. OpenAI cancellation.** TS passes the signal to `create` and, when the stream ends with the signal aborted, throws `APIUserAbortError` (`Request was aborted.`), which `_rewrapError` passes through. Choice: race every event with `CancelSignal::cancelled()`; on cancel drop the HTTP stream and yield `ModelError("Request was aborted.")`; the agent loop treats any error after a cancel as the cancel. TS reference: `model.ts:293-295,325-327`, `__tests__/responses.test.ts:165`. Files: `src/models/openai.rs`.

**P-203. OpenAI error mapping.** `classify_openai_error(status, code, message)` ports TS `classifyOpenAIError` (429, `rate_limit_exceeded` code, three rate-limit phrases, `context_length_exceeded` code, eight overflow phrases). Throttling becomes `ModelThrottledError` (with the API error as source), overflow `ContextWindowOverflowError`; otherwise connection and timeout errors become `ModelNetworkError` (section 10), other API errors `ModelError`, and non-API failures (an `apiKey` setter error, an unparseable event) `Error::Other`. TS rethrows the last three untouched. TS reference: `models/openai/errors.ts`, `model.ts:337-352`. Files: `src/models/openai/errors.rs`, `src/models/openai.rs`.
