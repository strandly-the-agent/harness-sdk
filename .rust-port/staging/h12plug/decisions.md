# Pending decisions, track h12plug (P-910 to P-929)

**P-910. `TodoStatus` and `TodosConfig` are public names although the TS package entry exports neither (h12plug).** TS `TodoItem.status` is a string union and `new Todos({..})` takes an object literal, so neither needs a name there; Rust needs a named enum for the three statuses and a nameable config struct to call `Todos::new`. Both are re-exported from the crate root beside `Todos` and `TodoItem`. `TodosConfig` is exhaustive with `Default` and a `bon` builder (#65).

**P-911. `todo_write` publishes the TS input schema literally and validates leniently (h12plug).** The spec's `inputSchema` is the JSON the TS SDK's `tool()` produces from the zod schema (generated with the built TS SDK and pinned in `the_tool_spec_is_the_one_ts_publishes`), set with `FunctionTool::with_input_schema`. The handler parses with the schemars-derived schema of the Rust input struct, which accepts unknown keys as zod's non-strict `z.object` does (TS strips them; the published schema says `additionalProperties: false` in both SDKs).

**P-912. The TS case `registers a context injector on initAgent` asserts the effect, not the registration call (h12plug).** `LocalAgent::new` and `MiddlewareRegistry::has` are crate-private in the SDK, so the Rust test builds an agent with the plugin and a mock model and asserts the model sees the reminder only once a list is stored. No SDK change made.

**P-913. `EnvironmentContext` reads the platform from the sandbox, as TS at the pin does, not from `std::env::consts::OS` (h12plug).** The track brief names `std::env::consts::OS` (the donor's behaviour, an older TS baseline). TS at the pin probes `uname -s` through the sandbox (`if ($IsLinux -or $IsMacOS) { uname -s } else { 'Windows' }` in a PowerShell sandbox) and the working directory with `echo "$PWD"`, and its tests assert it ("Platform and cwd come from the sandbox probe, not the host process"); the port follows TS. Only the date is native (`jiff::Zoned::now().date()`, the local calendar date).

**P-914. `EnvironmentMemo`, `render_environment` and `AGENTS_MD_CAP` are `pub(crate)` (h12plug).** TS exports them from the module for its tests but not from the package entry. `render_environment(sandbox: Option<&Arc<dyn Sandbox>>, shells: &ShellCache, memo: &EnvironmentMemo) -> String` takes the sandbox instead of the agent (TS reads `agent.sandbox` and nothing else), with `None` for the TS "sandbox getter throws" branch; the plugin owns the `ShellCache` and each `init_agent` call owns its memo (a `tokio::sync::OnceCell`).

**P-915. The TS case `reports the real working directory from the local sandbox shell` is ported without changing the working directory (h12plug).** TS `chdir`s to a fresh directory and builds a harness; tests here never `set_current_dir`, and `NotASandboxLocalEnvironment` has no working-directory option, so the Rust test renders through `NotASandboxLocalEnvironment::new()` and compares the probe with `std::env::current_dir()` (read only) and the host platform. Unix only (`#[cfg(unix)]`).

**P-916. `sandbox.rs` loses its file-level `expect(dead_code)` (h12plug, edit outside the track's paths).** The environment plugin uses `SandboxShell`, `ShellCache::shell_of` and `SHELL_PROBE`, so the expectation was unfulfilled and nothing in the file is unused any more. The web_fetch track makes the same edit.
