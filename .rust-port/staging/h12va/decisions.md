**P-1210. `shutdown_telemetry` is final for the process: the harness keeps a shut-down state.** Review findings correctness-b-1 and api-b-5. The SDK keeps the tracer provider in its own process-wide slot and returns a clone of it to every later `setup_tracer` call, so a `create_harness` after a `shutdown_telemetry` got the shut-down provider back and the next `shutdown_telemetry` failed with `AlreadyShutdown`. Options: (a) a third slot state, `ShutDown`, so setup after a shutdown does nothing and a later shutdown returns `Ok(())`; (b) map `OTelSdkError::AlreadyShutdown` to `Ok(())` and keep calling `setup_tracer`; (c) replace the SDK's provider so a later harness is traced again (needs an SDK change: `setup_tracer` has no way to drop its slot). Choice: (a). It makes no SDK call that cannot succeed and states the limit in the rustdoc: a harness created after the call is not traced. A shutdown while nothing was wired leaves the state unset, so a later `create_harness` with a selector still sets tracing up. `AlreadyShutdown` is still returned when the caller shut the SDK's provider down through its own handle before `shutdown_telemetry`; that is the caller's second shutdown of one provider and is left as the error it is.

**P-1211. `agentConfig.caching: "auto"` of a portable config is `CachingOption::On`.** Review finding correctness-b-5. TS spreads `agentConfig` into the `createHarness` options, and there any `caching` value that is passed, `'auto'` included, is an explicit request: a model without prompt caching throws instead of warning. `CachingOption::Auto` is the Rust spelling of "not passed" (P-957), so a value read from JSON cannot map to it. Options: (a) map `"auto"` to `On` (`true, true`, the TS meaning); (b) keep `Auto` and add a divergence row. Choice: (a); the divergence row for `caching: 'auto'` stays about the `create_harness` option only. The values are now: `"auto"` and `true` are `On`, `false` and `null` are `Off`, an absent key leaves `Auto`.

**P-1212. The harness `Debug` impls also redact a server's `url` and `args`; P-1212 amends P-1122.** Review finding correctness-b-6, harness half. `redact_mcp_servers` now prints a `url` as scheme, host, port and path (no userinfo, no query string, no fragment), parsed with `reqwest::Url`, already a dependency; a value that is not a string, does not parse or has no host prints as `<redacted>`. `args` prints as a count, the string `[N redacted]`, or `<redacted>` when it is not an array. Options for `url`: (a) keep the query keys and replace the values (`?key=<redacted>`), the reviewer's form; (b) drop the query string, the form the brief of track `h12vb` sets for the SDK's `McpServerConfig`. Choice: (b), so both crates print one shape. Known limits: the path is printed, so a key carried in a path segment is visible; the URL parser lower-cases the host, so a `${VAR}` placeholder used as the host prints in lower case; a `url` that is a placeholder as a whole prints as `<redacted>`.
