# Phase 8 decisions (staging; numbered from P-260)

**P-260. Sandbox module shape and the name map; P-260 adds to the P-15 name map.** TS `sandbox/{base, types, constants, posix-shell, not-a-sandbox-local-environment, stream-process}.ts` become `strands::sandbox::{base, types, constants, posix_shell, not_a_sandbox_local_environment, stream_process}`, re-exported from `strands::sandbox`. `Sandbox` is an `async_trait` trait (decision #36) whose streaming methods return `BoxStream<'a, Result<ExecutionEvent>>` borrowing `&self`, so an implementation can stream from its own state; `execute`, `execute_code`, `read_text`, `write_text` and `get_tools` are provided methods. New names: `ExecutionEvent` (TS has the anonymous union `StreamChunk | ExecutionResult`; variants `StreamChunk` and `ExecutionResult`), `SandboxSource` (the `sandbox` config key, TS `Sandbox | false`, variants `Sandbox(Arc<dyn Sandbox>)` and `Off`), and crate-internal `AgentSandbox`, `ProcessSpec`, `ProcessLimits`, `Utf8Decoder`. `ExecuteOptions` is an exhaustive config struct with a `bon` builder: `timeout: Option<Duration>` (TS seconds), `cwd: Option<String>`, `cancel_signal: Option<CancelSignal>` (TS `signal`), `env: Option<BTreeMap<String, String>>`. `StreamChunk`, `FileInfo`, `OutputFile` and `ExecutionResult` are `#[non_exhaustive]` with public fields, `new(..)` and `with_*`. Exit codes are `i32`, sizes `u64`. Error texts that name TS methods (`executeStreaming() did not yield an ExecutionResult`) keep the TS text. TS reference: `sandbox/base.ts`, `sandbox/types.ts`, `sandbox/index.ts`, `index.ts:403-413`. Files: `src/sandbox.rs`, `src/sandbox/`.

**P-261. `PosixShellSandbox` is a trait with a blanket `Sandbox` impl.** TS `PosixShellSandbox` is an abstract class whose subclasses implement only `executeStreaming` and may override any other method (the shell tests override `execute`). Options: free helper functions (the donor's choice, which loses the TS name), a wrapper struct, or a trait mirroring every `Sandbox` method with shell defaults plus `impl<T: PosixShellSandbox> Sandbox for T`. Choice: the trait; every provided method can be overridden in the `PosixShellSandbox` impl and the blanket impl forwards. Consequence: calling a method on a concrete type that implements `PosixShellSandbox` with both traits in scope is ambiguous (E0034); call through `dyn Sandbox` or a qualified path. A downstream crate can still implement `Sandbox` directly for its own types (`tests/sandbox.rs`). TS reference: `sandbox/posix-shell.ts`. Files: `src/sandbox/posix_shell.rs`.

**P-262. `build_shell_env_prefix`, `validate_env_keys` and `shell_quote` are public.** TS exports them from `posix-shell.ts`/`constants.ts` but neither `sandbox/index.ts` nor `index.ts` re-exports them, while the `PosixShellSandbox` docs tell implementers to prepend `buildShellEnvPrefix` (see the TS bug entry). Choice: public in `strands::sandbox`, so a Rust `PosixShellSandbox` can apply `env` as documented. `ENV_KEY_PATTERN` stays crate-internal (a validator, not a regex, is the useful form); `LANGUAGE_PATTERN` is a public `&str`. Files: `src/sandbox.rs`, `src/sandbox/constants.rs`.

**P-263. `NotASandboxLocalEnvironment` is public and per agent; no process-global default slot.** TS keeps the type internal and registers one instance in a process-global `defaultSandbox` slot at import (`register-node-defaults.ts`). Section 11 item 39 forbids that registration. Choice: the type is public under its TS name (`strands::sandbox::NotASandboxLocalEnvironment`, so the harness and users can share one), and an agent without a `sandbox` key builds its own instance (the type is stateless). `default-slot.ts` is not ported. TS reference: `sandbox/default.ts`, `sandbox/register-node-defaults.ts`, `default-slot.ts`. Files: `src/sandbox.rs`, `src/sandbox/not_a_sandbox_local_environment.rs`.

**P-264. `sandbox: SandboxSource::Off` fails with `DefaultNotConfiguredError`.** TS `get sandbox()` returns `this._sandbox || defaultSandbox.get()`, so on Node `sandbox: false` behaves like an unset key and runs on the host (`default.test.node.ts` "treats sandbox: false the same as unconfigured"); the error appears only where no default is registered (browsers). Section 12 Phase 8 requires `sandbox: false` to produce `DefaultNotConfiguredError` when a tool needs a sandbox, and Rust has no environment without a host default. Choice: follow the design. `Agent::sandbox()`, `LocalAgent::sandbox()` and `ToolAgent::sandbox()` return `Result<Arc<dyn Sandbox>>`, and `Off` yields `Error::DefaultNotConfigured` with the TS slot message. Logged in DIVERGENCES. TS reference: `agent/agent.ts:320-333,491-501`, `sandbox/default.ts`. Files: `src/sandbox.rs`, `src/types/agent.rs`, `src/agent/agent.rs`.

**P-265. Agent wiring: the shared-file edits.** `agent/config.rs`: one `sandbox: Option<SandboxSource>` field (`#[builder(into)]`) and its import. `agent/agent.rs`: `Agent::new` sets the sandbox (one line), `Agent::sandbox()`, and in `initialize` the TS loop that registers sandbox-vended tools before plugins, skipping a name the user registered with the TS debug text; only an explicitly configured sandbox vends tools (TS `if (this._sandbox)`). `types/agent.rs`: an `AgentSandbox` field on `LocalAgent` and `ToolAgentInner`, `sandbox()` on both views, crate-internal `agent_sandbox()`/`set_sandbox()`. `AgentSandbox` also carries an `Arc<()>` owner token that identifies the agent for per-agent host state (the `bash` sessions, P-270). TS reference: `agent/agent.ts:885-905`. Files: those three.

**P-266. Process spawning: groups, termination and decoding.** `stream_process` spawns through `process-wrap` with `ProcessGroup::leader()` (Unix) or `JobObject` (Windows) plus `KillOnDrop` (P-5, section 11 item 42b). On timeout or cancel it sends `SIGTERM` to the group (Windows: kill) and returns the error at once, as TS does; a spawned, instrumented reaper sends `SIGKILL` to the group after TS's one-second grace. Dropping the stream kills the group. An already-cancelled signal fails before spawning (TS spawns and kills at once; the result is the same error). stdin is always a pipe: written and closed when `input` is set, otherwise held open for the life of the stream (TS "keeps stdin open"). Output is decoded incrementally like Node's `StringDecoder` (split sequences held, invalid bytes become U+FFFD). Signal exits map to `128 + n` for TS's eight named signals and `128 + 1` otherwise. TS reference: `sandbox/stream-process.ts`. Files: `src/sandbox/stream_process.rs`.

**P-267. Local sandbox seams.** Section 9.4 forbids `set_current_dir` and env mutation in tests. Choice: crate-internal `NotASandboxLocalEnvironment::with_base_dir` (the default cwd and the base of relative paths; production reads `std::env::current_dir()` per call, as TS reads `process.cwd()`), `with_sleeper` (timeouts and the kill grace wait on the injected sleeper, so tests never wait for a timer), and a `host_env` function pointer (Windows merges the host environment with `env`; tests inject a fixed one). The POSIX/PowerShell command construction is a pure function tested for both platforms on every host. Non-Unicode host variables are dropped from the Windows child environment. Files: `src/sandbox/not_a_sandbox_local_environment.rs`, `src/sandbox/test_sandbox.rs`.

**P-268. `list_files` order and `read_text` decoding.** TS sorts entries with `localeCompare` and decodes with a non-fatal `TextDecoder`. Choice: sort by lowercase name, then by bytes (no ICU collation); `read_text` decodes lossily. Files: `src/sandbox/not_a_sandbox_local_environment.rs`, `src/sandbox/base.rs`.
