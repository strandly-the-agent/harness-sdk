# Phase 8 decisions (staging; numbered from P-260)

**P-260. Sandbox module shape and the name map; P-260 adds to the P-15 name map.** TS `sandbox/{base, types, constants, posix-shell, not-a-sandbox-local-environment, stream-process}.ts` become `strands::sandbox::{base, types, constants, posix_shell, not_a_sandbox_local_environment, stream_process}`, re-exported from `strands::sandbox`. `Sandbox` is an `async_trait` trait (decision #36) whose streaming methods return `BoxStream<'a, Result<ExecutionEvent>>` borrowing `&self`, so an implementation can stream from its own state; `execute`, `execute_code`, `read_text`, `write_text` and `get_tools` are provided methods. New names: `ExecutionEvent` (TS has the anonymous union `StreamChunk | ExecutionResult`; variants `StreamChunk` and `ExecutionResult`), `SandboxSource` (the `sandbox` config key, TS `Sandbox | false`, variants `Sandbox(Arc<dyn Sandbox>)` and `Off`), and crate-internal `AgentSandbox`, `ProcessSpec`, `ProcessLimits`, `Utf8Decoder`. `ExecuteOptions` is an exhaustive config struct with a `bon` builder: `timeout: Option<Duration>` (TS seconds), `cwd: Option<String>`, `cancel_signal: Option<CancelSignal>` (TS `signal`), `env: Option<BTreeMap<String, String>>`. `StreamChunk`, `FileInfo`, `OutputFile` and `ExecutionResult` are `#[non_exhaustive]` with public fields, `new(..)` and `with_*`. Exit codes are `i32`, sizes `u64`. Error texts that name TS methods (`executeStreaming() did not yield an ExecutionResult`) keep the TS text. TS reference: `sandbox/base.ts`, `sandbox/types.ts`, `sandbox/index.ts`, `index.ts:403-413`. Files: `src/sandbox.rs`, `src/sandbox/`.

**P-261. `PosixShellSandbox` is a trait with a blanket `Sandbox` impl.** TS `PosixShellSandbox` is an abstract class whose subclasses implement only `executeStreaming` and may override any other method (the shell tests override `execute`). Options: free helper functions (the donor's choice, which loses the TS name), a wrapper struct, or a trait mirroring every `Sandbox` method with shell defaults plus `impl<T: PosixShellSandbox> Sandbox for T`. Choice: the trait; every provided method can be overridden in the `PosixShellSandbox` impl and the blanket impl forwards. Consequence: calling a method on a concrete type that implements `PosixShellSandbox` with both traits in scope is ambiguous (E0034); call through `dyn Sandbox` or a qualified path. A downstream crate can still implement `Sandbox` directly for its own types (`tests/sandbox.rs`). TS reference: `sandbox/posix-shell.ts`. Files: `src/sandbox/posix_shell.rs`.

**P-262. `build_shell_env_prefix`, `validate_env_keys` and `shell_quote` are public.** TS exports them from `posix-shell.ts`/`constants.ts` but neither `sandbox/index.ts` nor `index.ts` re-exports them, while the `PosixShellSandbox` docs tell implementers to prepend `buildShellEnvPrefix` (see the TS bug entry). Choice: public in `strands::sandbox`, so a Rust `PosixShellSandbox` can apply `env` as documented. `ENV_KEY_PATTERN` stays crate-internal (a validator, not a regex, is the useful form); `LANGUAGE_PATTERN` is a public `&str`. Files: `src/sandbox.rs`, `src/sandbox/constants.rs`.

**P-263. `NotASandboxLocalEnvironment` is public and per agent; no process-global default slot.** TS keeps the type internal and registers one instance in a process-global `defaultSandbox` slot at import (`register-node-defaults.ts`). Section 11 item 39 forbids that registration. Choice: the type is public under its TS name (`strands::sandbox::NotASandboxLocalEnvironment`, so the harness and users can share one), and an agent without a `sandbox` key builds its own instance (the type is stateless). `default-slot.ts` is not ported. TS reference: `sandbox/default.ts`, `sandbox/register-node-defaults.ts`, `default-slot.ts`. Files: `src/sandbox.rs`, `src/sandbox/not_a_sandbox_local_environment.rs`.

**P-264. `sandbox: SandboxSource::Off` fails with `DefaultNotConfiguredError`.** TS `get sandbox()` returns `this._sandbox || defaultSandbox.get()`, so on Node `sandbox: false` behaves like an unset key and runs on the host (`default.test.node.ts` "treats sandbox: false the same as unconfigured"); the error appears only where no default is registered (browsers). Section 12 Phase 8 requires `sandbox: false` to produce `DefaultNotConfiguredError` when a tool needs a sandbox, and Rust has no environment without a host default. Choice: follow the design. `Agent::sandbox()`, `LocalAgent::sandbox()` and `ToolAgent::sandbox()` return `Result<Arc<dyn Sandbox>>`, and `Off` yields `Error::DefaultNotConfigured` with the TS slot message. Logged in DIVERGENCES. TS reference: `agent/agent.ts:320-333,491-501`, `sandbox/default.ts`. Files: `src/sandbox.rs`, `src/types/agent.rs`, `src/agent/agent.rs`.

**P-265. Agent wiring: the shared-file edits.** `agent/config.rs`: one `sandbox: Option<SandboxSource>` field (`#[builder(into)]`) and its import. `agent/agent.rs`: `Agent::new` sets the sandbox (one line), `Agent::sandbox()`, and in `initialize` the TS loop that registers sandbox-vended tools before plugins, skipping a name the user registered with the TS debug text; only an explicitly configured sandbox vends tools (TS `if (this._sandbox)`). `types/agent.rs`: an `AgentSandbox` field on `LocalAgent` and `ToolAgentInner`, `sandbox()` on both views, crate-internal `agent_sandbox()`/`set_sandbox()`. `AgentSandbox` also carries an `Arc<()>` owner token that identifies the agent for per-agent host state (the `bash` sessions, P-270). TS reference: `agent/agent.ts:885-905`. Files: those three.

**P-266. Process spawning: groups, termination and decoding.** `stream_process` spawns through `process-wrap` with `ProcessGroup::leader()` (Unix) or `JobObject` (Windows) plus `KillOnDrop` (P-5, section 11 item 42b). On timeout or cancel it sends `SIGTERM` to the group (Windows: kill) and returns the error at once, as TS does; a spawned, instrumented reaper sends `SIGKILL` to the group after TS's one-second grace. Dropping the stream kills the group. An already-cancelled signal fails before spawning (TS spawns and kills at once; the result is the same error). stdin is always a pipe: written and closed when `input` is set, otherwise held open for the life of the stream (TS "keeps stdin open"). Output is decoded incrementally like Node's `StringDecoder` (split sequences held, invalid bytes become U+FFFD). Signal exits map to `128 + n` for TS's eight named signals and `128 + 1` otherwise. TS reference: `sandbox/stream-process.ts`. Files: `src/sandbox/stream_process.rs`.

**P-267. Local sandbox seams.** Section 9.4 forbids `set_current_dir` and env mutation in tests. Choice: crate-internal `NotASandboxLocalEnvironment::with_base_dir` (the default cwd and the base of relative paths; production reads `std::env::current_dir()` per call, as TS reads `process.cwd()`), `with_sleeper` (timeouts and the kill grace wait on the injected sleeper, so tests never wait for a timer), and a `host_env` function pointer (Windows merges the host environment with `env`; tests inject a fixed one). The POSIX/PowerShell command construction is a pure function tested for both platforms on every host. Non-Unicode host variables are dropped from the Windows child environment. Files: `src/sandbox/not_a_sandbox_local_environment.rs`, `src/sandbox/test_sandbox.rs`.

**P-268. `list_files` order and `read_text` decoding.** TS sorts entries with `localeCompare` and decodes with a non-fatal `TextDecoder`. Choice: sort by lowercase name, then by bytes (no ICU collation); `read_text` decodes lossily. Files: `src/sandbox/not_a_sandbox_local_environment.rs`, `src/sandbox/base.rs`.

**P-269. Vended tool shape and the name map; P-269 adds to the P-15 name map.** TS `makeX(sandbox?, options?)` overloads and `export const x = makeX()` become `make_x(MakeXOptions) -> FunctionTool` with the bound sandbox as an options field (`sandbox: Option<Arc<dyn Sandbox>>`), and `x() -> FunctionTool` for the default instance (a `const` can't hold a tool). `make_shell` returns `Result<FunctionTool>` because TS throws at construction for a bad `defaultTimeout`. Tools are `FunctionTool`s over a fixed schema, so `invoke(input, context)` works as in TS; the schemas are the exact `z.toJSONSchema` output at the pin (generated from the TS zod definitions). Input is validated by `jsonschema` (P-51 texts); where a TS test asserts a zod custom message (`offset must be a positive 1-indexed line number`, ...), a precheck returns that text. `ShellOutput`, `BashOutput` and the error types `ShellTimeoutError`, `ShellExecutionError`, `BashTimeoutError`, `BashSessionError` are public structs with `NAME`; Rust has no class hierarchy, so `ShellTimeoutError` is not also a `BashTimeoutError`. `MakeShellOptions::input_schema` is a raw JSON schema (TS a zod type). `default_timeout` is a `Duration`. TS's "Tool context is required" checks have no Rust equivalent (a tool always gets a context). Not ported: the deprecated `makeBash`, `MakeBashOptions`, `SANDBOX_BASH_DESCRIPTION` and the bash barrel re-exports. The read tool returns its image or document as `ToolResultContent` JSON, which `FunctionTool` turns into the content block. TS reference: `vended-tools/{shell, read, write, edit}/`. Files: `src/vended_tools.rs`, `src/vended_tools/`.

**P-270. `bash` sessions.** TS keeps one process per agent in a module-global `WeakMap`, kills them from `process` exit/SIGINT handlers, and runs on the host (not the sandbox). Choice: sessions live in the tool instance (no process-global state), keyed by the agent's `AgentSandbox` owner token (P-265) through a `Weak`, so a dropped agent's entry is pruned and dropping the tool kills every session (`KillOnDrop`, own process group). Still host-spawned, as in TS. Each command writes its sentinel to stdout and to stderr, and the result is taken once both arrive, so the command's stderr can't land after the result (TS waits only for the stdout sentinel and can drop late stderr). The start directory uses the crate-internal `bash_with(cwd, sleeper)` seam; production reads the process cwd. TS reference: `vended-tools/bash/bash.ts`. Files: `src/vended_tools/bash.rs`.

**P-271. Item-3 vended tools: shapes and texts.** Same shape as P-269: `make_python_repl`, `make_notebook`, `make_sleep`, `make_stop` return `Result<FunctionTool>` (TS throws at construction), `make_handoff_to_user` returns `FunctionTool`, and `python_repl()`, `notebook()`, `http_request()`, `sleep()`, `stop()`, `handoff_to_user()` build the defaults. `sleep_description` is the TS `sleepDescription`; `MakeSleepOptions::max_duration` is a `Duration`; `DEFAULT_MAX_DURATION` is `Duration::from_secs(60)`. Numbers echoed in texts (`Slept for 0.05 seconds`, `Command timed out after 0.1 seconds`, `got 0`) format like JS `String(n)`. `python_repl` passes the invocation's cancel signal to `execute_code`; a cancel propagates as `SandboxAbortError` (`Execution aborted`), a timeout as the sandbox timeout text plus the partial-output JSON line, and any other sandbox failure as `PythonReplError` with the cause as source. `stop` calls `ToolAgent::cancel` with `after_current_tools: true`. `handoff_to_user` raises the `strands:handoff-to-user` interrupt through `ToolContext::interrupt` with the message as the reason. `notebook` keeps notebooks in app state under `notebooks` (insertion order, as the TS `Record`); `readRange` and numeric `insertLine` are JSON numbers, and a fractional insert line is "Line number out of range" (TS splices at the truncated index). Cancellation messages of `sleep`: the cancel reason, else TS's `Sleep cancelled` / `Sleep cancelled before it started`. TS reference: `vended-tools/{python-repl, notebook, http-request, sleep, stop, handoff-to-user}/`. Files: `src/vended_tools/`.

**P-272. `http_request` over `reqwest`, with a capped body.** TS calls `fetch` and reads the whole body with `response.text()`. Section 11 item 32 requires stream-capping HTTP bodies. Choice: one `reqwest::Client` per tool; the body is read with `bytes_stream` and the call fails with `Response body exceeds the 10485760-byte limit: <METHOD> <url>` once it passes 10 MiB (TS has no cap; the value matches the read tool's media cap). `statusText` is the canonical reason phrase (reqwest doesn't expose the server's); headers are keyed by lowercase name in sorted order with repeats joined by `, `, as `Headers.forEach` yields them. The timeout (default 30 s) and the invocation cancel race the request (`Request timed out after <n> seconds: ...`, `Request cancelled: ...`). Redirects follow reqwest's default policy (fetch follows too). `url` is validated with `format: uri`. The timeout waits on the crate-internal `http_request_with(sleeper)` seam in tests; tests use a local TCP server. Files: `src/vended_tools/http_request.rs`.

**P-273. Sleep and timeout seams.** `sleep` waits on an injected sleeper (crate-internal `make_sleep_with`); `bash` (`bash_with`) and `http_request` (`http_request_with`) take one for their timeouts; production uses the tokio timer. No test waits on a real timer; process tests wait only for child processes. Files: `src/vended_tools/{sleep, bash, http_request}.rs`.

**P-280. `web_fetch` over `reqwest`, `htmd` and `encoding_rs`.** TS calls `fetch` and `turndown`. Choice: one `reqwest::Client` per tool; each call is one `GET` with the TS `User-Agent` and `Accept` headers; the whole fetch races the invocation cancel signal (`Web fetch tool request cancelled`, also mid-body); no timeout (TS has none); the body is streamed and capped at `max_bytes` with the TS text; the TS error texts (`url=<..> | fetch failed: invalid URL`, `... only http and https URLs are supported`, `... fetch failed: <error>`, `HTTP <status> <statusText>: GET <url>`) are kept, with the canonical reason phrase as `statusText` (P-272). The body is decoded with the content type's `charset` through `encoding_rs::Encoding::for_label` (the WHATWG labels `TextDecoder` takes), else UTF-8, removing a matching BOM as `TextDecoder` does; `encoding_rs` becomes a direct dependency (it was already in the lock through reqwest's `charset` feature). `max_bytes` and `max_content_chars` are `usize`: zero is rejected with the TS text (`maxBytes must be a positive number, got 0`), and NaN, negative and infinite values are unrepresentable. Content is cut by `char`, not UTF-16 unit (section 7.3). The converter is configured once in a `OnceLock` (the TS cached turndown service): ATX headings, fenced code, `-` bullets, inlined links, the TS dropped elements skipped with their subtree, and handlers for `title` (`# <title>`), `img` and `a` with the TS scheme rules; the scheme comes from `reqwest::Url` (WHATWG, as `new URL`) after stripping leading `\p{Cc}\p{Cf}\p{Zs}`. The result is trimmed and ends with one newline. `mode` is the `#[non_exhaustive]` enum `WebFetchMode { Markdown, Agentic }` (TS `'markdown' | 'agentic'`, default agentic). Agentic mode builds a fresh analyst `Agent` per call (TS analyst prompt, printer off) on `options.model`, else the calling agent's `aux_model` (which falls back to its model), and invokes it with the tool's cancel signal and `InvocationContext::auxiliary(..)` so its usage adds to the request without its limits. The TS `agentic mode requires a model` error can't happen in Rust: a `ToolContext` always has an agent with a model. New names: `WebFetchMode`. TS reference: `vended-tools/web-fetch/{web-fetch, extract, types}.ts`. Files: `src/vended_tools/web_fetch.rs`, `src/vended_tools/web_fetch/`, root and `strands` `Cargo.toml`.
