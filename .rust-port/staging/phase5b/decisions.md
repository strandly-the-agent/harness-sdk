# Pending decisions from Phase 5 item 2 (`AnthropicModel`)

Format as in `.rust-port/DECISIONS-pending.md`; the lead folds these in.

**P-180. Anthropic module, names and options; P-180 adds to the P-15 name map.** TS `models/anthropic.ts` exports `AnthropicModel`, `AnthropicModelConfig` (extends `BaseModelConfig`) and `AnthropicModelOptions` (config plus `apiKey`, `client`, `clientConfig`). Choice: `strands::models::anthropic` behind the `anthropic` feature with `AnthropicModel`, `AnthropicModelConfig` (flat: the six base fields plus `stop_sequences`, `params: Option<JsonObject>`, `anthropic_tools: Option<Vec<JsonValue>>`, `betas`, `use_native_token_count`, `cache_config`, with `merge`), `AnthropicModelOptions { api_key, client_config, config }` and the new name `AnthropicClientConfig { base_url, default_headers: http::HeaderMap, max_retries, timeout }` for the subset of the vendor SDK's `ClientOptions` the Rust client honours. `AnthropicModel::new(impl Into<AnthropicModelOptions>) -> Result<Self>` (`From<AnthropicModelConfig>` lets a bare config through); typed `config()` (TS `getConfig`, resolved) and `update_config(AnthropicModelConfig) -> Result<()>` (TS throws on function tools in `anthropicTools`), beside the trait's `get_config`/`update_config`. The TS `client` option (a pre-built vendor SDK client such as `AnthropicBedrock`) has no Rust equivalent; the client is a crate-internal `MessagesClient` trait that unit tests replace. Server tools stay raw JSON because their shapes are open-ended and versioned by the API; the harness web search is `anthropic_tools: [{ "type": "web_search_20260318", "name": "web_search", "allowed_callers": ["direct"] }]`. `Debug` for the options, client config (header names only) and model never prints the key. TS reference: `models/anthropic.ts:262-372`. Files: `src/models/anthropic.rs`.

**P-181. The vendor SDK transport, reproduced over `reqwest`.** Decision #68 asks for the `@anthropic-ai/sdk` transport. Read from `node_modules/@anthropic-ai/sdk` 1.4.0 (`client.js`, `core/streaming.js`, `core/error.js`, `lib/BetaMessageStream.js`): `POST {base}/v1/messages` (beta: `?beta=true`; tokens: `/v1/messages/count_tokens`) with `content-type: application/json`, `anthropic-version: 2026-10-21` and `x-api-key` (marked sensitive), then `ANTHROPIC_CUSTOM_HEADERS` lines, then `client_config.default_headers`, then the per-request `anthropic-beta`; each layer replaces same-named headers of the one before, as the SDK's `buildHeaders` does. Env defaults through a crate-internal lookup seam, trimmed, empty treated as unset: `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_CUSTOM_HEADERS`. Not read: `ANTHROPIC_AUTH_TOKEN` (Strands TS refuses to build a client without an API key, and the SDK prefers the key when both are set), `ANTHROPIC_LOG`, `ANTHROPIC_WEBHOOK_SIGNING_KEY` and the SDK 1.x profile credential chain. Retry: `max_retries` 2 on connection errors, timeouts and statuses 408, 409, 429, >= 500, with `x-should-retry` deciding first; the wait is `retry-after-ms`, else `retry-after` seconds or HTTP date (`jiff::fmt::rfc2822`), used when `0 < ms <= 2^31-1`, else `min(0.5 * 2^n, 8) s * (1 - 0.25 * random)`. The timeout (default ten minutes) covers the wait for response headers only, as the SDK arms it around `fetch`, and is a race against the injectable `Sleeper`, so tests time out without waiting. No retry once the body streams. SSE through `eventsource-stream`: `ping` and unnamed events (which the crate names `message`) are skipped, `error` events become a status-less API error, other events are parsed JSON. Error text follows `APIError.makeMessage` (`"{status} {body.message | JSON body | text}"`, `"{status} status code (no body)"`, `Connection error.`, `Request timed out.`). Jitter draws from `fastrand` (P-46). Not sent: `User-Agent` and the `x-stainless-*` telemetry headers. TS reference: `@anthropic-ai/sdk/client.js:600-930`. Files: `src/models/anthropic/client.rs`.

**P-182. Anthropic error mapping.** TS `_translateError` returns `ContextWindowOverflowError` for the six phrases (case-insensitive), `ModelThrottledError` for status 429, and otherwise the SDK error itself (`APIError` subclasses; `streamAggregated` wraps them in `ModelError`). Decision #68 adds that transport failures are `ModelNetworkError`. Choice: overflow phrases, then 429, then connection and timeout errors as `ModelNetworkError` (source: the API error), other API errors (status errors, stream `error` events, the pause-turn limit) as `ModelError` with the API error as source, and non-API failures and TS `throw new Error(..)` cases (formatting, missing key, removed sampling params) as `Error::Other` with the TS text. Only 429 is throttled; 408, 5xx and 529 stay `ModelError` after the transport retry. Logged as a divergence. TS reference: `models/anthropic.ts:666-683`. Files: `src/models/anthropic.rs`.

**P-183. Anthropic error texts name Rust options.** Three TS messages name TS options or the installed SDK: the missing-key text (`'apiKey' option`), the sampling-param rejection's origin (`the default for @anthropic-ai/sdk 1.4.0`, `pinned by clientConfig.defaultHeaders['anthropic-version']`) and its fix hint (`clientConfig: { defaultHeaders: { 'anthropic-version': '2023-06-01' } }`). Options: keep TS text verbatim, or name the Rust options. Choice: Rust names (`'api_key' option`; `the AnthropicModel default`; `pinned by client_config.default_headers['anthropic-version']`; `set 'anthropic-version': '2023-06-01' in client_config.default_headers`); the `ANTHROPIC_CUSTOM_HEADERS` origin and every other text are TS-exact. No cross-SDK test reads these. TS reference: `models/anthropic.ts:363-367,831-863`. Files: `src/models/anthropic.rs`, `src/models/anthropic/format.rs`.

**P-184. The API version is that of `@anthropic-ai/sdk` 1.x.** TS resolves the default `anthropic-version` from the installed SDK major (`2023-06-01` on 0.x, `2026-10-21` from 1.0) and skips the local sampling-param check for an injected client. Choice: Rust sends `2026-10-21` unless a header pins one, so `temperature`, `top_p` and `top_k` are rejected locally with the TS text until `anthropic-version: 2023-06-01` is pinned, and assistant PDF documents are skipped with the TS warning. The TS `on @anthropic-ai/sdk 0.x` cases (2) are gaps. TS reference: `models/anthropic.ts:254-258,846-849`. Files: `src/models/anthropic.rs`, `src/models/anthropic/format.rs`.

**P-185. Pause-turn continuations resend the accumulated message.** TS resends `stream.finalMessage().content`, the vendor SDK's snapshot of the paused response. Rust has no SDK stream object, so the provider folds every raw event into a `MessageSnapshot` (the SDK's accumulation rules: text, citations, buffered tool input parsed at block stop, thinking, signature and compaction deltas, cumulative `message_delta` usage) and resends its `content`. The same snapshot gives the compaction request's final message. The TS test's mock `finalMessage()` returns only the `server_tool_use` block; the ported test expects the text block the real snapshot holds too. TS reference: `models/anthropic.ts:607-619,736-738`. Files: `src/models/anthropic/stream.rs`, `src/models/anthropic/tests/anthropic_tools.rs`.

**P-186. Anthropic test seams.** Unit tests never touch env, time or the network. Choice: crate-internal `AnthropicModel::with_seams(options, Seams { env, warn_once, sleeper, random, transport })`, where `transport` is `Http`, `Built(client)` (resolved like the `reqwest` client: key check and API version from headers and env, as the TS tests' mocked constructor) or `Injected(client)` (the TS `client` option: no key check, unknown API version). `warn_once` is injectable because the process-wide warn-once set would hide repeated construction warnings across tests (TS mocks `warnOnce`). Transport tests run a tokio TCP server in the test; no new dev-dependency. Files: `src/models/anthropic.rs`, `src/models/anthropic/tests.rs`, `src/models/anthropic/client/tests.rs`.

**P-187. Cancellation of an Anthropic call.** TS passes no abort signal to `messages.stream`; cancellation stops consumption. Choice: the same; `ModelRequest::cancel_signal` is not read by the provider, and dropping the stream drops the in-flight `reqwest` future. `summarize` passes the signal to the client-side fallback as TS does. TS reference: `models/anthropic.ts:467-470`. Files: `src/models/anthropic.rs`.

**P-188. Shared model code touched.** The `count_tokens` fallback needs the default heuristic (TS `super.countTokens`), which Rust trait overrides can't call. Choice: `models::model::estimate_tokens_heuristic` becomes `pub(crate)`; no other shared file changes. Files: `src/models/model.rs`, `src/models/mod.rs` (module declaration).
