**P-480. Agent spans are `tracing` spans; static keys are fields, dynamic keys and events go through `tracing-opentelemetry`.** TS `Tracer` starts OpenTelemetry spans directly. Choice: `telemetry::tracer::LocalTracer` (the existing local tracer, extended in place) opens one `tracing::info_span!` per TS span with the static callsite names `invoke_agent`, `execute_agent_loop_cycle`, `chat` and `execute_tool`; the TS span name (`invoke_agent <name>`, `execute_tool <tool>`) is the `otel.name` field, which `tracing-opentelemetry` exports as the span name. Every `gen_ai.*` key the span may record is declared as an empty field (31 fields, under the `tracing` limit of 32) and recorded with `Span::record`, so any `tracing` subscriber sees them and unset keys aren't exported. The keys are crate constants (`telemetry::tracer::keys`). Counts are recorded as `i64` (a `u64` recorded after span creation is exported as a string by `tracing-opentelemetry` 0.34). Status is the `otel.status_code = "OK"` field, or `otel.status_description = <message>` on an error (the layer maps it to an error status). Dynamic keys (`trace_attributes`, the `name` attribute, the latest-convention content keys under `gen_ai_span_attributes_only`/Langfuse) and span events (`gen_ai.user.message`, `gen_ai.choice`, `gen_ai.client.inference.operation.details`, `exception`, ...) use `OpenTelemetrySpanExt::{set_attribute, add_event}` and exist only with the `otel` feature; without it message content isn't serialized at all. TS reference: `telemetry/tracer.ts:255-1365`. Files: `src/telemetry/tracer.rs`.

**P-481. Span parenting.** As TS: the agent span parents under the current span, cycle spans under the agent span, `chat` and `execute_tool` spans under the cycle span, all by explicit `parent:` (the spans are kept in the tracer like TS `_agentSpan`/`_loopSpan`), so tool tasks spawned on other tasks parent correctly. The tool body runs inside its `execute_tool` span (`span.in_scope` around `tool.stream`, `.instrument(span)` around each poll), so a nested agent's `invoke_agent` span and the MCP trace context (P-247) parent under it. The earlier `debug_span!("tool_call")` around each tool task is replaced by `.in_current_span()`: it would be exported as a span TS doesn't have. The agent span starts just before the first cycle and ends when the cycles return (TS starts it before registering the structured-output tool; nothing is traced in between). Files: `src/agent/run.rs`, `src/tools/executors/executor.rs`.

**P-482. Semantic-convention settings are read once per agent through an env seam.** `telemetry::config::Semconv::from_env(EnvLookup)` reads `OTEL_SEMCONV_STABILITY_OPT_IN` (`gen_ai_latest_experimental`, `gen_ai_tool_definitions`, `gen_ai_span_attributes_only`), Langfuse (`LANGFUSE_BASE_URL`, or `langfuse` in `OTEL_EXPORTER_OTLP_ENDPOINT`/`OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`) and `OTEL_SERVICE_NAME` (default `strands-agents`, exported as `telemetry::DEFAULT_SERVICE_NAME`) when the agent's tracer is created, as the TS `Tracer` constructor does; tests set it with the crate-internal `LocalTracer::set_semconv`. `resource_attributes(EnvLookup)` builds the TS `getOtelResource` attributes, with `telemetry.sdk.language = "rust"` and `OTEL_RESOURCE_ATTRIBUTES` pairs over the defaults. Files: `src/telemetry/config.rs`.

**P-483. `trace_attributes` is typed and isn't written into `AgentTrace`.** `AgentConfig::trace_attributes: IndexMap<String, telemetry::AttributeValue>` (`String`, `Bool`, `Int`, `Float` and their arrays, with `From` impls) is merged into every span after the span's own attributes (TS merge order). The local `AgentTrace` keeps the TS shape (`metadata` holds only `cycleId`, `toolUseId`, `toolName`): the conformance fixture `telemetry/agent_traces.json` comes from a run with trace attributes and has none in it, so adding them would be Rust-only output. This departs from the brief's "recorded in `AgentTrace`". Files: `src/agent/config.rs`, `src/agent/agent.rs`, `src/telemetry/tracer.rs`.

**P-484. Attribute JSON.** `telemetry::json::to_json` is `serde_json::to_string` with `"<replaced>"` when serialization fails. The TS replacer targets `bigint`, functions, symbols and raw buffers, which typed Rust values can't hold; binary content is already base64 text in the wire form, exactly what TS `toJSON()` hands the replacer. Latest-convention parts take a block's TS `type` as its wire key plus `Block` (`reasoning` gives `reasoningBlock`). Files: `src/telemetry/json.rs`, `src/telemetry/tracer.rs`.

**P-485. `gen_ai.tool.definitions` has no caller.** As in TS, the agent never passes `toolsConfig` to `startAgentSpan`, so the attribute is recorded only when a caller of `LocalTracer::start_agent` supplies `tools_config` under `gen_ai_tool_definitions`. Files: `src/agent/run.rs`.
