**P-642. `Ask::Stdio` reads stdin on its own thread behind one process-wide queue.** Review findings correctness-1 and correctness-2. A Rust caller can drop an invocation while its prompt waits, which TS can't. Options: keep the read on the runtime's blocking pool (the orphaned read swallows the next answer and holds up runtime shutdown), or own the read outside the future. Choice: a `static` `tokio::sync::Mutex<Option<oneshot::Receiver<io::Result<String>>>>` is both the queue and the read in flight; a prompt takes its turn, writes the prompt (stdout is locked for the write only), then awaits the pending read or starts one on a detached `std::thread` (`strands-hitl-stdin`); a dropped prompt leaves the read for the next prompt to adopt. The queue is per process where the TS one is per handler, because stdin is per process (DIVERGENCES row staged). The answer is trimmed with `js_trim`. Files: `src/vended_interventions/hitl.rs`.
