# Track h12vb decisions (pending)

**P-1220. The strip of undeclared keys follows `prefixItems` (SDK).** Review finding correctness-b-3. `strip_unknown_properties` (behind `InputValidator::parse` and `StructuredOutputSchema::of`) takes the schema of an array element from `prefixItems` by index and from `items` for the elements after the prefix, which is how JSON Schema 2020-12 assigns them and what `schemars` prints for a Rust tuple. A field of type `(Inner, u32)` now accepts `[{"a": "x", "z": 1}, 2]` as zod does for `z.tuple([z.object(..), z.number()])`. The cases P-1195 lists as still rejected (`anyOf`/`oneOf` branches, record values, recursive `$ref` types) are unchanged.

**P-1221. A model call whose cancel signal already fired ends at the terminal without a request (SDK).** Review finding correctness-b-4. The wait of P-1141 in the background-task `BeforeModelCallEvent` hook returns when the invocation is cancelled, and the loop's only cancel check was before the hooks, so `Model::stream` was called with a history ending in an assistant message (the terminal's `select!` polls the provider first). `ModelTerminal::stream` now checks the signal first and yields the cancel error (`Agent invocation cancelled`) without starting a model span or building the request. This is the Rust form of the TS `_streamFromModel` checkpoint: the hooks, the continuation a hook added, the `InvokeModelStage` handlers and `AfterModelCallEvent` (with the cancel error, never retried) all run as in TS; only the provider is not reached. The check is on the cancel signal, so a deferred cancel (`after_current_tools`, design 0019) is not affected: it does not trip the signal and is still read at the post-batch checkpoint. Not chosen: returning `Stop::Cancelled` right after the hooks (no `AfterModelCallEvent` for a fired `BeforeModelCallEvent`, and a continuation added by a hook would be neither appended nor abandoned).

**P-1222. `McpServerConfig` `Debug`: `url` without userinfo, query string and fragment; `args` as a count (SDK).** Review finding correctness-b-6, SDK half; extends P-1199. `url` is parsed with `reqwest::Url` and printed as `scheme://host[:port]/path`; a value that does not parse or has no host prints as `<redacted>`, since nothing in it can be told apart from a key. The query string is dropped whole rather than printed with its values replaced (the report's form): a query parameter name can itself be the key in some services, and the brief asks for scheme, host, port and path only. `args` prints as `<N redacted>` (`Some(<3 redacted>)`), since an argument can be a token (`--token <value>`) and no rule separates flags from values. `command`, `cwd`, `transport`, `prefix`, `tool_filters`, `disabled` and `continue_on_error` print as before. `McpServers::Map` prints through the same impl; the builder and `McpServers::Json` were already opaque (P-1199).

**P-1223. `StdioServerParameters` `Debug` redacts `env` values and counts `args` (SDK).** Not from the review; closes the open item of P-1199. The derived `Debug` is replaced by a manual one (exhaustive destructuring, so a new field cannot be left out silently) that prints `env` names with `<redacted>` values and `args` as `<N redacted>`, the forms of P-1199 and P-1222. `args` is included, beyond the brief's `env`, because a `McpServerConfig` is resolved into these parameters and its `args` would otherwise be printed whole one step later. `StdioServerParametersBuilder` no longer derives bon's `Debug` (it printed the members that were set) and prints as its type name through `opaque_builder_debug!`; its `Debug` no longer depends on the builder state. The crate-private `ResolvedTransport` still derives `Debug` (its `Sse`/`Http` variants hold the url and headers); it is not printed outside tests.
