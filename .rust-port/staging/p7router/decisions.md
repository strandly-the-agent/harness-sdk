**P-450. Model routing placement and names; P-450 adds to the P-15 name map.** TS `models/routing/` exports `ModelRouter`, `RoutingCandidate`, `FallbackStrategy`, `ClassifierStrategy` and the types `ModelRouterOptions`, `RoutingCandidateOptions`, `ClassifierStrategyOptions`, `CandidateInput`, `RoutingAttempt`, `RoutingContext`, `RoutingStrategy`. Choice: `strands::models::routing` (private `strategy`, `fallback_strategy`, `classifier_strategy`, `router` modules, re-exported at the module root; nothing added to the crate root, so `lib.rs` is untouched). Same names except: `CandidateModel` (Rust-only enum `{ Model(Arc<dyn Model>), Router(ModelRouter) }` for TS's `Model | ModelRouter` union, `#[non_exhaustive]`, with `From<M: Model>`, `From<Arc<M>>`, `From<Arc<dyn Model>>`, `From<ModelRouter>`); `RoutingException` (P-453); no `RoutingCandidateOptions` (constructor `RoutingCandidate::new(model)` plus `with_name`, `with_description`, `with_metadata`, section 7.5) and no `CandidateInput` (`ModelRouter::new` takes `impl IntoIterator<Item = impl Into<RoutingCandidate>>`, and `RoutingCandidate` has the same four `From` impls). `ModelRouter::new(models)` and `ModelRouter::with_options(models, ModelRouterOptions { strategy: Option<Arc<dyn RoutingStrategy>>, max_switches: Option<u32> })`; the options struct is exhaustive with `Default` and a `bon` builder whose `strategy` setter takes `impl RoutingStrategy`. `ModelRouter::NAME = "strands:model-router"`. `RoutingContext` and `RoutingAttempt` are `#[non_exhaustive]` records with public fields and constructors (`RoutingContext::new(candidates)` plus `with_*`; `RoutingAttempt::success` / `failure`) so a custom strategy can be unit tested. Files: `src/models/routing.rs`, `src/models/routing/*.rs`.

**P-451. Candidate and router identity.** TS compares candidates and models by object identity and freezes them. Choice: `RoutingCandidate` and `ModelRouter` are `Arc`-backed handles; `Clone` shares the identity, `RoutingCandidate`'s `PartialEq`/`Eq`/`Hash` compare that identity, and models are compared with `Arc::ptr_eq`. The `with_*` setters use `Arc::make_mut`, so evidence is set before the candidate is cloned or handed to a router (documented on the type). `metadata` is a `JsonObject`, so TS's `metadata must be an object`, `cannot be serialized` and `non-finite number` errors have no Rust path. TS's `models must be a sequence of candidates`, `candidate must be a Model or ModelRouter`, `strategy must implement RoutingStrategy`, `maxSwitches must be a non-negative integer` and `strategy.select must return a RoutingCandidate or undefined; got ...` are enforced by the types (`max_switches: Option<u32>`, `select` returns `Result<Option<RoutingCandidate>>`). TS subclasses of `RoutingCandidate` have no Rust counterpart; strategy-specific evidence goes in `metadata`.

**P-452. `RoutingStrategy::name`.** TS logs `strategy.constructor.name`. Choice: a provided trait method `fn name(&self) -> &str` whose default is the implementing type's name without its module path or generics (from `std::any::type_name`), so `FallbackStrategy` logs as in TS and a custom strategy needs no code; `ClassifierStrategy` overrides it with the literal. `select(&self, &RoutingContext) -> Result<Option<RoutingCandidate>>` through `async_trait`, object safe.

**P-453. `RoutingAttempt.exception` is a `RoutingException { name, message }`.** TS stores the `Error` object. `strands::Error` is not `Clone` and `AfterModelCallEvent` only lends it (`Option<&Error>`), so the attempt history can't own the error. Choice: a `#[non_exhaustive]` record with the TS error name (`Error::name()`) and the message, `From<&Error>`, `PartialEq`. `FallbackStrategy` only tests for presence, as in TS.

**P-454. Routing state lives in the router, keyed by agent identity.** TS stores a `RoutingState` in `invocationState` under `strands:modelRouting:<agent id>:<router id>`. Section 7.1 makes `invocation_state` user-only. Choice: the router keeps `Mutex<Vec<(Weak<()>, Option<RoutingState>)>>`, one entry per attached agent, keyed by the agent's identity token (`AgentSandbox::owner`, the token the `bash` sessions and the MCP router already use); the `BeforeInvocationEvent` (`SDK_FIRST`) and `AfterInvocationEvent` (`SDK_LAST`) hooks clear it, as in TS. The lock is never held across an await: the hook clones the state, works on the copy and writes it back. Entries of dropped agents are pruned on the next attach. The TS assertions on invocation-state keys become assertions that the caller's state is untouched.

**P-455. Attaching the router.** TS `Agent` calls `router.attachToAgent(this)` in the constructor (which calls `initAgent`), lists the router first in the plugin registry, and throws `ModelRouter must be passed through Agent({ model }), not plugins` when a `ModelRouter` is among `plugins`. Rust plugins initialize lazily on the first call, which would register the router's Input middleware after the agentic token-usage middleware. Choice: `Agent::new` calls the crate-internal `ModelRouter::attach_to_agent(&LocalAgent)` after the sandbox (the identity token) is set and before the token-usage middleware, which registers the Input middleware and the three hooks once per agent; `Plugin::init_agent` (first slot of `registration_order`) is then a no-op, and returns the TS error for an agent the router is not the model of. `Agent::new` rejects a plugin named `strands:model-router` with the same error at build time (`instanceof` is not available on `Arc<dyn Plugin>`; plugin names are unique per agent).

**P-456. `ClassifierStrategy` without the decision-model layer.** TS routes the classification through `DecisionModel.ask` and wraps a plain `Model` in `LLMDecisionModel`; `decisions/` is out of v0.1. Choice: `ClassifierStrategy::new(Arc<dyn Model>)` and `with_options(Arc<dyn Model>, ClassifierStrategyOptions) -> Result`, making the single call `LLMDecisionModel._ask` makes for the one routing question: the same system prompt with its mandatory rules, the user text `{"latestRequest", "agentInstructions", "candidates"}`, the `strands_structured_output` tool spec zod generates for `{ candidate: { answer: enum(keys) } }` (bytes checked against the built TS SDK), forced tool choice, and a cancel signal that the timeout cancels. The answer must be one of the keys; anything else is a classification error (zod's enum check in TS), so TS's separate `index === -1` branch is folded into it and `error_type` is always logged. Usage is added to the routing context's invocation context after a successful decision, as `DecisionModel.ask` does. Options: `routing_policy: Option<String>`, `timeout: Option<Duration>` (zero is rejected with the TS text `timeoutMs must be finite and greater than zero`; the JS timer ceiling has no Rust counterpart), and `max_message_chars`, `max_agent_instructions_chars`, `max_candidate_chars: Option<NonZeroUsize>` (TS's `must be a positive integer` is type-enforced). The deprecated `systemPrompt` is out. The decision-model spec file stays out of scope.

**P-457. Shared-file edits for routing.** `agent/config.rs`: `ModelSource::Router(ModelRouter)` with `From<ModelRouter>` (section 8.4) and `ModelSource::into_aux_model`, which returns TS's `auxModel must be a Model or a Bedrock model id, not a ModelRouter`. `agent/agent.rs`: `model_router` field, model resolution, the aux-model, plugin and attach steps of P-455, the router as the first plugin, and `agent_metadata()`. `agent/run.rs`: `routed_model()` and `next_attempt_count()` (TS `_modelForAttempt`, `_nextAttemptCount`), a pre-terminal failure attributed to the routed model, `CancelledError` made `pub(crate)` (re-exported from `agent/mod.rs`) so the router can skip cancelled calls, and the model terminal now sends `agent_metadata` (the session id when a session manager is attached), which the loop did not forward before; the `forwards the agent metadata to the routed alternate` case needs it. `tools/structured_output.rs`: `INSTRUCTION` made `pub(crate)` for the classifier's tool spec.
