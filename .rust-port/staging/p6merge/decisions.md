**P-391. The drop warning covers unsaved memory (#64); P-391 extends P-91.** TS `shutdown()` is `await this.memoryManager?.flush()`, and `Symbol.asyncDispose` runs it when an `await using` scope exits, on a normal exit and on a throw; an agent that is neither shut down nor bound with `await using` flushes nothing and logs nothing. Rust has no async drop, so the `await using` guarantee can't be given, and decision #64 says the drop warning fires when shutdown work is pending. Choice: `Drop for Agent` logs a second warning, `agent dropped with conversation not yet saved to memory; call shutdown().await before dropping it` (with `agent_id`), when the agent's memory manager holds a buffered message that some extraction store hasn't saved (`MemoryManager::has_unsaved`, crate-internal, over the new `ExtractionCoordinator::has_unsaved`: the pending buffer is non-empty). That is the work `flush` would do: turns the trigger hasn't fired for, and saves still running in the background (which a runtime shutting down would cut off). No warning for an agent without a memory manager, with recall-only stores, never initialized, or after a `shutdown()` whose saves succeeded. Two accepted edges: after a `shutdown()` whose save failed the buffer is still held, so the warning repeats what the `memory extraction failed` log said; and a caller who keeps their own `MemoryManager` handle and calls `flush()` after dropping the agent sees a warning they don't need. Files: `src/agent/agent.rs` (`Drop`, `shutdown` docs), `src/memory/memory_manager.rs`, `src/memory/extraction/coordinator.rs`, `src/agent/run/tests/shutdown.rs`.

**P-392.
