**P-390. One injection engine; `MemoryInjectionConfig.trigger` is an `InjectionConfig`; supersedes P-353.** TS `memory/memory-manager.ts` imports `isUserTurn` and `createInjectionMiddleware` from `injection/message-injection.ts` and the escapes from `injection/xml.ts`, and `MemoryInjectionConfig extends InjectionConfig`. The memory manager now calls `crate::injection::{create_injection_middleware, InjectionMiddlewareOptions, render_content, is_user_turn, escape_xml_text, escape_xml_attr}`; `src/memory/injection.rs` and its public `InjectionPredicate` and three-variant `InjectionTrigger` are deleted. `strands::memory` re-exports `InjectionConfig`, `InjectionTrigger` and `InjectionContext` from `strands::injection` (TS `memory/index.ts` re-exports the same three from `../injection/index.js`; the brief's note that TS exports them only from `injection/` is not what the pin does). The TS union `InjectionTrigger | predicate` stays the private `Trigger` (P-380), so the inherited field is `MemoryInjectionConfig.trigger: Option<InjectionConfig>` (`#[builder(into)]`, with a new `From<InjectionTrigger> for InjectionConfig`): `.trigger(InjectionTrigger::EveryTurn)` or `.trigger(InjectionConfig::new().with_trigger_fn(..))`. A memory trigger predicate therefore returns `bool` (P-381) where the deleted helper took `Result<bool>`; no TS memory case covers a throwing predicate. With the memory manager as a user, the module-level `allow(dead_code, unused_imports)` is gone from `injection.rs`, and the `Folded`, `apply_injection` and `fold_into_last_user_message` re-exports are removed (still used inside `injection/message_injection.rs`, as in TS). Files: `src/injection.rs`, `src/injection/types.rs`, `src/memory.rs`, `src/memory/types.rs`, `src/memory/memory_manager.rs`.
