## Findings

1. `harness-rs/strands-harness/src/tools/programmatic_tool_caller/run.rs:222-227` (via `programmatic_tool_caller.rs:110`): an inner call that a `BeforeToolCallEvent` hook cancels (an intervention deny) reaches the guest as `Tool '<name>' error: <cancel message>`, because `call_tool` returns the cancel as `ToolCallOutcome::Result` with an error status (`strands-rs/strands/src/tools/executors/executor.rs:311-320`). TS raises `Failed to execute tool '<name>': <cancel message>`: `gateInnerCall` throws the refusal (`harness-ts/src/tools/programmatic-tool-caller.ts:278-287`) inside the `try` whose `catch` at `:358` adds that prefix. Evidence: scratch binary `dump/src/bin/deny.rs` (hook `set_cancel("DENIED: shell is off")`, the TS `gatedCode`) prints `ERR Tool 'shell_like' error: DENIED: shell is off`; TS gives `ERR Failed to execute tool 'shell_like': DENIED: shell is off` (TS side by reading). `DIVERGENCES.md:23` records only the default message, and `deny_blocks_the_inner_call_and_the_tool_never_runs` (`tests.rs:671`) asserts only `contains("DENIED: shell is off")`, so nothing pins the prefix. Fix: let `ToolCallOutcome` tell a hook cancel from a tool's own error result so `run.rs` uses the `Failed to execute tool` prefix; or widen the DIVERGENCES row to the whole text and assert the full string.

2. `harness-rs/strands-harness/src/tools/file_tools.rs:170-177` (`offset`, `limit`) and `tools/web_fetch.rs:411` (`prompt`): the key order inside optional schema properties differs from TS. TS (zod `.optional().describe(..)`, `file-tools.ts:96-97`, `web-fetch.ts:222-228`) serializes `{"description":"…","type":"number"}`; Rust serializes `{"type":…,"description":…}`. Evidence: `npx tsx` dump of `toolSpec` vs `serde_json::to_string(&tool.tool_spec())` (`ts-dump.txt` / `rs-dump.txt`): `read` first differs at byte 438, `web_fetch` at byte 551. The `the_tool_spec_matches_the_typescript_tool` / `tool_specs_match_the_typescript_tools` tests (`web_fetch/tests.rs:720`, `file_tools/tests.rs:421`) compare `serde_json::Value`s, whose equality ignores key order even with `preserve_order`, so they cannot catch it. Fix: put `description` before `type` in those three properties and assert on the serialized string.

3. `strands-rs/strands/src/types/agent.rs:635`: inner calls get the tool-use id `call_<uuid v7 simple>`; TS uses `ptc_<uuid>` (`programmatic-tool-caller.ts:337`). Hooks, tool spans and `AfterToolCallEvent` observe the id. Neither `DIVERGENCES.md` nor `DECISIONS-pending.md` mentions `ptc_` (grep). Fix: let `call_tool` take the id or a prefix and pass `ptc_`, or add a DIVERGENCES row.
