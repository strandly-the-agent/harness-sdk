# Phase 4 review: API bar-raiser (commit f5e53f220)

Probes: scratch `.rs` files compiled with `rustc --extern strands=/tmp/cargo-target-review4/debug/libstrands.rlib` (all features); output in `/tmp/review4_api-bar-raiser_probes.txt`. A control probe building `CancelOptions` and `BackgroundTasksConfig` with `..Default::default()` compiles, so the setup is sound.

1. `strands-rs/strands/src/conversation_manager/sliding_window_conversation_manager.rs:144` and `strands-rs/strands/src/conversation_manager/summarizing_conversation_manager.rs:22`: both config structs are `#[non_exhaustive]`. That breaks the #65 rule (PROMPT 7.5: "Never put `#[non_exhaustive]` on a config struct") and the AGENTS.md rule that config structs carry `#[expect(clippy::exhaustive_structs, ...)]`. Evidence: `SlidingWindowConversationManagerConfig { window_size: 10, ..Default::default() }` and `SummarizingConversationManagerConfig { preserve_recent_messages: 4, ..Default::default() }` from another crate both fail with `error[E0639]: cannot create non-exhaustive struct using struct expression`. Sibling config structs compile fine (`CancelOptions`, `BackgroundTasksConfig`, `TakeSnapshotOptions`). Fix: swap `#[non_exhaustive]` for the standard `#[expect(clippy::exhaustive_structs, reason = "config struct: struct-literal construction")]`, and add a struct-literal case to `tests/api_surface.rs`.

2. `strands-rs/strands/src/agent/agent.rs:348`: `Agent::cancel_signal()` can only be called while the agent is idle, and then it always returns a fresh, uncancelled signal (`types/agent.rs:417-420` `end_cancel`). Its doc ("The cancellation signal of the running invocation") can never hold. Evidence: reading `agent.cancel_signal()` while an `agent.stream(..)` is alive fails with `error[E0502]: cannot borrow *agent as immutable because it is also borrowed as mutable`. Hooks get `LocalAgent` and tools get `ToolAgent`, never `Agent`. TS `cancelSignal` (agent.ts:1061, types/agent.ts:413) is read from inside the run, which Rust already covers with `LocalAgent::cancel_signal`, `ToolAgent::cancel_signal` and `ExecuteToolContext::cancel_signal`. Fix: remove `Agent::cancel_signal` and drop it from the P-90 name list.

3. `strands-rs/strands/src/background_tasks/types.rs:56`: `pub enum BackgroundTasks` reuses a TS name for a different construct. In TS, `BackgroundTasks` is the plugin class (`background-tasks/background-tasks.ts:49` `export class BackgroundTasks implements Plugin`; `agent.ts:570` `_backgroundTasks: BackgroundTasks`). The config-key union `boolean | BackgroundTasksConfig` (`agent.ts:246`) has no TS name. Rust renames the TS class to an invented `BackgroundTaskScheduler` (`background_tasks/mod.rs`) and gives its name to the union. P-95 lists both as "new names" but doesn't record that one TS name now points at another concept, which section 7.1 says needs a logged reason. Fix: keep `BackgroundTasks` for the crate-internal plugin and give the union a new, logged name (for example `BackgroundTasksOption`, like `ModelSource` and `SandboxSource`). If the current name stays, record the repurposing in the P-15 name map.

4. `strands-rs/strands/src/plugins/registry.rs:16,28,36`: a plugin init failure is stored as `String` and replayed as `Error::other(..)`. The first `initialize` returns the plugin's typed error, but every later `invoke`/`initialize` returns `Error::Other`, so `Error::name()`, variant matching and the `source()` chain all change between the first and second call. TS shares one rejected promise, so every caller gets the same error object (`plugins/registry.ts:26,31` "subsequent calls share the first initialization result, including failures"). This follows from the code: a plugin whose `init_agent` returns `Err(Error::ContextWindowOverflow(..))` yields `ContextWindowOverflowError` on the first call and `"Error"` on the retry. Fix: store the failure as `Arc<Error>` and replay it through a private error type that shows the same text and returns the original as `source()`. Or make the replayed error keep the original's `name()`.

5. `strands-rs/strands/src/conversation_manager.rs:143`: the public extension trait `ConversationManager` has no doc example, and neither do `conversation_manager.rs`, its submodules or `background_tasks/` (`grep -c '//[/!] \`\`\`'` gives 0 for every file in both). `Plugin` (`plugins/plugin.rs:19`) and `MiddlewareStage` (`middleware/types.rs:55`) both have compiling examples. TS documents the trait with an `@example` (`conversation-manager/conversation-manager.ts:98-109`, `Last10MessagesManager`). Fix: port that example as a doctest on the trait (a `reduce` that drains `options.agent_mut().messages_mut()`, wired up with `.conversation_manager(..)`). Add a short builder example on `SlidingWindowConversationManagerConfig` and on `AgentConfig::background_tasks`/`BackgroundTasksConfig`.

6. `strands-rs/strands/src/conversation_manager/sliding_window_conversation_manager.rs:143`: `SlidingWindowConversationManagerConfig` derives `Copy`, as P-96 chose. I disagree. Adding any non-`Copy` field later (for example a `model`, like its sibling `SummarizingConversationManagerConfig.model: Option<Arc<dyn Model>>` at `summarizing_conversation_manager.rs:25`) removes `Copy`, which breaks downstream code. Under #65, config structs are meant to grow through `..Default::default()`. The Phase 2 review made the same point about `Copy` on `ModelInfo`. Fix: derive `Clone` only.

Checked with no finding: `AgentStreamStage` is exported only from `strands::middleware`, not the crate root (`lib.rs:58-73`). `std::any::Any`/`TypeId` appear only inside `middleware/registry.rs` (logged in P-94), not in public signatures. There are no tokio types in Phase 4 public signatures. `CancelOptions`, `BackgroundTasksConfig`, `TakeSnapshotOptions` and `InterruptParams` are exhaustive with `Default` and builders. Events, results, contexts and enums are `#[non_exhaustive]`. TS-internal persisted types (`InterruptStateData`, `PendingToolExecution`), `ContinuationInput`, the token-usage middleware and the compression helpers are `pub(crate)`. Plugin names match TS (`strands:sliding-window-conversation-manager`, `strands:background-tasks`, `strands:model`, `strands:agent-delegation`). `cargo doc -p strands --all-features --no-deps` emits no rustdoc warnings.

Verdict: accept with conditions. Fix 1 to 3 before the phase closes; 4 to 6 are small follow-ups.
