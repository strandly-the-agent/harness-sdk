3. `strands-rs/strands/src/conversation_manager/token_usage_middleware.rs:22-26`: `percent` rounds the exact fraction `used/limit` half-up. TS formats the double `((used / limit) * 100).toFixed(1)` (`strands-ts/src/context-manager/modes/agentic/agentic-context.ts:198`), which rounds the binary value. This also contradicts P-96's "`toFixed(1)`-style half-up rounding". Evidence: at the default limit 200000 (`models/model_info.rs:172`), used=300 gives TS `0.1` and Rust `0.2`. A node sweep of used=1..limit over limits {200000, 128000, 1000000, 8192} gives 1230 mismatches. The middleware isn't installed yet (`allow(dead_code)` at `:65-68`, Phase 6), so no user sees the text today. Fix (identical to `toFixed(1)` on all 1,336,592 values I checked):
   ```rust
   fn percent(used: u64, limit: u64) -> String {
       let x = used as f64 / limit as f64 * 100.0;
       // `{:.1}` rounds exact ties to even; `toFixed` rounds them up. An exact tie is an odd multiple of 0.25.
       let q = x * 4.0;
       if q.fract() == 0.0 && q % 2.0 == 1.0 { format!("{:.1}", x + 0.05) } else { format!("{x:.1}") }
   }
   ```
   Add `percent(300, 200_000) == "0.1"` to `rounds_percent_ties_up_like_to_fixed` (`token_usage_middleware/tests.rs:176`), and correct P-96.
