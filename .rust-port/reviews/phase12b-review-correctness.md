**correctness-b-1.** `harness-rs/strands-harness/src/telemetry.rs:148-161` (`shutdown_telemetry`) with `strands-rs/strands/src/telemetry/config/setup.rs:292-296`: the second `shutdown_telemetry()` of a process fails with `AlreadyShutdown` when a `create_harness` ran between the two calls, and that second harness traces nothing. `shutdown_telemetry` takes the provider out of the harness slot and shuts it down, but the SDK keeps the same provider in its own process-wide slot (`TRACER_PROVIDER`). The next `create_harness` finds the harness slot empty, calls `strands::telemetry::setup_tracer` again, gets a clone of the shut-down provider back (`tracer provider already initialized, returning existing provider`) and stores it; the next `shutdown_telemetry` calls `shutdown()` on it, which `opentelemetry_sdk` 0.33.1 answers with `Err(OTelSdkError::AlreadyShutdown)` (`trace/provider.rs:246-269`). The disposition row of correctness-8 says "a second call does nothing"; that holds for two calls in a row, the only case the unit tests cover. A program that runs one harness per job and flushes after each (`create_harness` → `invoke` → `shutdown_telemetry` in a loop) gets an error on the second job.
Evidence: `/tmp/review12b_correctness/probe/tests/telemetry.rs` (`OTEL_TRACES_EXPORTER=console`, mock model), `cargo test --offline --test telemetry -- --nocapture`:
```
shutdown before setup: Ok(())
first shutdown: Ok(())
shutdown again, no harness between: Ok(())
shutdown after a second create_harness: Err(Sdk(Other(AlreadyShutdown)))
```
`probe/tests/telemetry_after.rs` (same setup, one `invoke` per step): the agent built before the call and the one built after it both still answer (`Ok("hi")`), the console exporter prints the three spans of the first invocation only, and the closing `shutdown_telemetry()` is again `Err(Sdk(Other(AlreadyShutdown)))`.
Fix: keep the fact that the harness has shut its provider down (a third slot state, `Shutdown`, instead of `take()` back to `None`), so `setup` after a shutdown does not call `setup_tracer` again and a later `shutdown_telemetry` returns `Ok(())`; or map `OTelSdkError::AlreadyShutdown` to `Ok(())`. Add the create → shutdown → create → shutdown case to `telemetry/tests.rs`, and say in the rustdoc that a harness created after the call is not traced (today it says only "agents that run after it").
