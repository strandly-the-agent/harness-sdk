**P-1. Commit with `--no-verify`.** Context: the husky pre-commit hook builds and tests strands-ts on every commit, and this branch changes no TS. Options: run the hook, skip it. Choice: `git commit --no-verify` for every commit. TS reference: `.husky/pre-commit`. Files: all commits.

**P-2. Branch return.** Context: the sandbox is not persistent across sessions, and the environment's instructions say work survives only by pushing a branch. Options: keep local only, push. Choice: push only this branch, only to the `strandly-the-agent/harness-sdk` fork, as `feat/rust-sdk-fresh` (the existing `feat/rust-sdk` there is an earlier attempt, left untouched). Files: none.

**P-3. Rust CI job scope.** Context: the brief gives the MSRV command as `cargo check --workspace`, but CI is split into a `strands-rs` and a `harness-rs` area. Options: `--workspace` in both areas, or per-area packages. Choice: every cargo command in `strands-rs-test-lint.yml` uses `-p strands -p strands-macros` and in `harness-rs-test-lint.yml` uses `-p strands-harness` (MSRV included), all with `--locked`. Tests run as `--all-targets` plus a separate `--doc` step, each for `--all-features` and `--no-default-features`. Linux runner only, no Windows leg. The conformance step also fails on untracked fixture files, which `git diff --exit-code` alone misses. TS reference: none. Files: `.github/workflows/strands-rs-test-lint.yml`, `.github/workflows/harness-rs-test-lint.yml`.

**P-4. Rust workflow wiring and cargo-deny.** Context: the repo has two patterns: `ci.yml` calls `typescript-pr-and-push.yml`/`mcp-pr-and-push.yml` (they have `workflow_call`, no concurrency) and calls `harness-*-test-lint.yml` directly (their pr-and-push files are push-only with concurrency). Choice: `rust` calls `strands-rs-pr-and-push.yml` (test-lint plus `rust-security-audit.yml`); `harness-rust` calls `harness-rs-test-lint.yml`; `harness-rs-pr-and-push.yml` is push-only. cargo-deny runs only from the SDK area, because it checks the whole workspace and any dependency change touches the root `Cargo.lock`, which is in that area's filter. Advisories run with `continue-on-error`, like the repo's npm and pip audits and the cargo-deny-action README matrix; bans, licenses and sources block. The action's image ships Rust 1.85, so it is given `rust-version: 1.96.0`. Files: `.github/workflows/ci.yml`, `.github/workflows/strands-rs-pr-and-push.yml`, `.github/workflows/harness-rs-pr-and-push.yml`, `.github/workflows/rust-security-audit.yml`.

**P-8. Conformance fixture format and TS-only cases.** Context: the generator needs a stable case format, and some TS values cannot come from TS runtime code. Options: record only TS output, or input plus output; hand-write type-only values or skip them. Choice: each fixture file is an object of named cases with `description` and some of `expected` (TS output in TS key order), `input`, `expectedText` (exact `JSON.stringify` text), `expectedError` and `shapeOnly`. `ToolChoice`, `Usage`, `Metrics` and a full `ToolSpec` are type-only in TS, so they are `shapeOnly`. Lone surrogates are recorded as `expectedText` only, because serde_json rejects them and one such value would make the whole file unparseable. Span `exception.stacktrace` is cut to its first line (stack frames name local paths). `strands-rs/conformance/package.json` (`"type": "module"`) exists only for top-level `await` under tsx, as section 11 item 24 asks. Internals not exported from the package entry points (`InterruptState`, `Stash`, `SnapshotStorageAdapter`, the session validators, `contentBlockFromSavedData`) are imported from their `dist` modules. TS reference: `strands-ts/src/tools/types.ts:13,76`, `strands-ts/src/models/streaming.ts:503,535`, `strands-ts/src/telemetry/tracer.ts:1031-1056`. Files: `strands-rs/conformance/`.
