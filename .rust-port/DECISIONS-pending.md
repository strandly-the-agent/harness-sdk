**P-16. Stream-event `redactedContent` is written as an index-keyed object.** Context: item 12. TS `JSON.stringify` writes `ReasoningContentDelta.redactedContent` (a `Uint8Array`) as `{"0":1,"1":2}`, while `ReasoningBlock.toJSON()` writes base64. Options: write base64 everywhere, or match each TS form. **P-17. Integer counters are `u64`.** Context: item 13. Choice: `Usage`, `Metrics` and citation positions and indices are `u64`, so they serialize without `.0`; a fractional value in those fields fails to load (TS never writes one). Free-form JSON stays `JsonValue`. Known gap for the fixture item: `serde_json` formats `f64` values differently from JavaScript in two places (`-0` becomes `-0.0`, JS writes `0`; integral floats from 2^64 up to 1e21 become `1.2345678901234567e+20`, JS writes all digits); `1e+21` and small exponents already match. JS never writes `-0`, so only TS-written floats above `u64::MAX` and below 1e21 would change bytes on re-save. A custom `serde_json::ser::Formatter` can close this if the fixture round trips need it. TS reference: `src/models/streaming.ts` (`Usage`, `Metrics`), `src/types/citations.ts`. Files: `models/streaming.rs`, `types/citations.rs`.

**P-18. Lone surrogates and the recursion limit.** Context: item 14. TS strings can hold lone UTF-16 surrogates and `JSON.stringify` writes them as `\ud83d`; a Rust `String` can't hold one, so `serde_json` rejects such text. Options: fail the load, or rewrite the escape. Choice: types parse with plain `serde_json` (a lone surrogate fails); the crate-internal `types::json::replace_lone_surrogates` rewrites unpaired `\uD800-\uDFFF` escapes to `\ufffd` (it skips escaped backslashes and keeps valid pairs) for the storage and session load paths to call before parsing. The recursion limit stays `serde_json`'s default of 128 nested levels (TS has none); the 64-deep fixture parses. Both are tested. TS reference: `strands-rs/conformance/fixtures/types/json_edge_cases.json`. Files: `types/json.rs`.

**P-19. Wire struct shape.** Context: #65. Choice: wire structs have public fields, `#[non_exhaustive]`, `new(..)` with the required fields and `with_*` for optional ones; `Message::tracking_id` is private with a getter and `with_tracking_id` (an empty id keeps the minted one, as TS `data.trackingId || generateTrackingId()`); `generate_tracking_id` is UUID v4 like TS `crypto.randomUUID()`. `PartialEq` is derived (all fields, including `tracking_id`), so no hand-written equality ignores fields. Option structs (`InterruptParams`, `TakeSnapshotOptions`) are exhaustive with `Default` and a `bon` builder. Every block's `Serialize`/`Deserialize` is TS `toJSON()`/`fromJSON()` (wrapped), so standalone blocks in events (`result: {"toolResult":..}`) need no adapter; the inner shapes come from private `#[serde(remote = ..)]` mirrors and the crate-internal `wrapped_serde!` macro. TS reference: `src/types/messages.ts`. Files: `types/*.rs`, `macros.rs`.
