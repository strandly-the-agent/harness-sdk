**P-17. Integer counters are `u64`.** Context: item 13. Choice: `Usage`, `Metrics` and citation positions and indices are `u64`, so they serialize without `.0`; a fractional value in those fields fails to load (TS never writes one). Known gap for the fixture item: `serde_json` formats `f64` values differently from JavaScript in two places (`-0` becomes `-0.0`, JS writes `0`; integral floats from 2^64 up to 1e21 become `1.2345678901234567e+20`, JS writes all digits); `1e+21` and small exponents already match. **P-18. Lone surrogates and the recursion limit.** Context: item 14. TS strings can hold lone UTF-16 surrogates and `JSON.stringify` writes them as `\ud83d`; a Rust `String` can't hold one, so `serde_json` rejects such text. Options: fail the load, or rewrite the escape. Choice: types parse with plain `serde_json` (a lone surrogate fails); the crate-internal `types::json::replace_lone_surrogates` rewrites unpaired `\uD800-\uDFFF` escapes to `\ufffd` (it skips escaped backslashes and keeps valid pairs) for the storage and session load paths to call before parsing. TS reference: `strands-rs/conformance/fixtures/types/json_edge_cases.json`. Files: `types/json.rs`.
