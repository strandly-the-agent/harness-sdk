# Pending decisions

**P-1. Commits skip the husky hook.** The pre-commit hook builds and tests strands-ts; the branch changes no TS. Options: run the hook, skip it. Choice: `git commit --no-verify` (section 9.5). Files: all commits.

**P-2. Branch returned by pushing to the agent's fork.** The run environment's sandbox does not persist between sessions and its instructions say to push work to a remote branch. Options: keep local only (lost on recycle), push. Choice: push only `feat/rust-sdk` to `strandly-the-agent/harness-sdk`; no PRs, issues or posts. Files: none.

**P-3. Shared build cache under a small disk.** About 5.5 GB free. Options: separate target dirs per reviewer (section 9.9), one shared target dir. Choice: builds use `CARGO_TARGET_DIR=$HOME/target` and `CARGO_PROFILE_DEV_DEBUG=line-tables-only`; reviewers share it (cargo's build lock serializes them) instead of `/tmp/review-target-<role>`. Files: `.rust-port/gates.sh`.

**P-4. Secret scan leaves `PROMPT.md` out of the pattern check.** The brief contains the scan regex itself, so the section 9.5 patterns always match it. Choice: `.rust-port/scan.sh` runs the patterns on the staged diff minus `.rust-port/PROMPT.md` and `scan.sh` itself (both contain the regex), runs the env-value check on the whole diff, and exits non-zero on a hit. Files: `.rust-port/scan.sh`.

**P-5. Dependency versions checked against crates.io on 2026-11-11.** Latest stable of each crate, with three adjustments. `monty` 1.6.0 declares `rust-version = 1.98`, above the 1.96 MSRV (#59); the workspace requires `monty = "1.5"` and resolver 3 locks 1.5.0 (rust-version 1.96). `syn` is 3.x and `darling` 0.24 (both on syn 3); `reqwest` is 0.13, the major `rmcp` 3.9 and `opentelemetry-otlp` 0.33 use. `cedar-policy` is pinned `=4.14.1` (it pins `cedar-policy-core =4.14.1`). Options: newest everywhere (breaks MSRV), pin older. Choice: as listed. Files: `Cargo.toml`, `Cargo.lock`.

**P-6. `reqwest`, `htmd` and `cedar-policy` are non-optional `strands` dependencies.** Vended `http_request`, `web_fetch` and `CedarAuthorization` are in v0.1 and the design names only five features. Options: extra features per vended tool, always on. Choice: always on (section 8.1). Files: `strands-rs/strands/Cargo.toml`.

**P-7. `aws-config` and `aws-sdk-bedrockruntime` feature trim.** Both with `default-features = false`; `aws-config`: `behavior-version-latest`, `credentials-process`, `default-https-client`, `rt-tokio`, `sso`; `aws-sdk-bedrockruntime`: `behavior-version-latest`, `default-https-client`, `rt-tokio` (its default `rustls` feature enables the legacy `tls-rustls` client). The lock has only hyper 1, h2 0.4, rustls 0.23 and rustls-webpki 0.103. `credentials-login` is left out until a user needs it. Files: `Cargo.toml`.

**P-8. `cargo deny` duplicate policy and targets.** With every v0.1 dependency, 26 crates resolve twice through transitive dependencies we don't control (syn 2 and 3, rand, phf, sha2 via `rmcp`'s `oauth2`, ruff crates via `monty`). Options: `multiple-versions = "deny"` with a long skip list, `warn` plus targeted denies. Choice: `multiple-versions = "warn"`, and `deny-multiple-versions` for crates where two copies would split types or runtime state (`reqwest`, `hyper`, `http`, `h2`, `rustls`, `tokio`, `serde_json`, `schemars`, `tracing`, `opentelemetry`, `opentelemetry_sdk`, `cedar-policy-core`, `aws-smithy-runtime`). `[graph] targets` lists the supported Linux, macOS and Windows targets, which drops `atomic-polyfill` (RUSTSEC-2023-0089, only on targets without atomics, via `monty` > `postcard` > `heapless`) without an ignore. Licenses add `BlueOak-1.0.0` (`minicbor`) and `Unicode-DFS-2016` (`unicode_names2`), both via `monty`. Files: `deny.toml`.

**P-9. Dependencies build without debug info in dev and test profiles.** The sandbox disk holds one full build plus the MSRV check only just. Options: keep the default, `[profile.dev.package."*"] debug = false`. Choice: the profile override in the root `Cargo.toml`; workspace crates keep line tables, so test backtraces still point into SDK code. Files: `Cargo.toml`.
