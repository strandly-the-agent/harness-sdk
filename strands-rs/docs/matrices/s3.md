# S3 storage — TS → Rust

Behind the `s3` cargo feature (`aws-config` + `aws-sdk-s3`). Two independent pieces:
`storage::S3Storage` (unified key/value `Storage`) and `session::S3SessionStorage`
(`SnapshotStorage`).

## API

| TS (`src/storage/s3-storage.ts`)            | Rust (`storage/s3_storage.rs`)                         |
| ------------------------------------------- | ------------------------------------------------------ |
| `new S3Storage({bucket, prefix, region, s3Client, searchStrategy})` | `S3Storage::builder(bucket).prefix().region().client().search_strategy().build().await` / `S3Storage::new(bucket)` |
| `write/read/delete/list/search`             | `Storage::{write,read,delete,list,search}`             |

| TS (`src/session/s3-storage.ts`)                       | Rust (`session/s3_storage.rs`)                              |
| ------------------------------------------------------ | ----------------------------------------------------------- |
| `new S3Storage({bucket, prefix, region, s3Client})`    | `S3SessionStorage::builder(bucket).prefix().region().client().build().await` / `S3SessionStorage::new(bucket)` |
| `saveSnapshot({location, snapshotId, isLatest, snapshot})` | `SnapshotStorage::save_snapshot(&location, snapshot_id, is_latest, &snapshot)` |
| `loadSnapshot({location, snapshotId?})`                | `load_snapshot(&location, Option<&str>)`                    |
| `listSnapshotIds({location, limit?, startAfter?})`     | `list_snapshot_ids(&location, Option<usize>, Option<&str>)` |
| `deleteSession({sessionId})`                           | `delete_session(&str)`                                      |
| `loadManifest` / `saveManifest`                        | `load_manifest` / `save_manifest`                           |

Key layout is byte-identical to TS/Python for prefixes without redundant or trailing separators:
`[<prefix>/]<session_id>/scopes/<scope>/<scope_id>/snapshots/{manifest.json,snapshot_latest.json,immutable_history/snapshot_<uuid7>.json}`.

## Tests

`session/__tests__/s3-storage.test.ts` → `session::s3_storage::tests` (38 mocked tests, `aws-smithy-mocks`);
`storage/__tests__/s3-storage.test.ts` → `storage::s3_storage::tests` (17 mocked tests).
Every TS `it(...)` has a snake_case counterpart; extra Rust tests: `returns_empty_vec_when_limit_is_zero`,
`rejects_a_start_after_cursor_that_is_not_a_uuid_v7`, `clamps_max_keys_for_a_limit_larger_than_a_page`,
`returns_empty_vec_when_the_bucket_is_missing`, `propagates_no_such_bucket_on_read`. Live round-trips: `tests/integ_s3.rs`
(`#[ignore = "live S3"]`, `STRANDS_TEST_S3_BUCKET`).

TS `it('rejects a scope containing path traversal')` has no Rust equivalent: `scope` is the `Scope`
enum, so there is no scope string to validate. Ported as `rejects_a_scope_id_containing_path_traversal`.
TS `it('returns null when S3 response has no body')` folds into
`returns_none_when_s3_response_body_is_empty` — the Rust SDK always yields a (possibly empty) `ByteStream`.

## Divergences

- Session type is named `S3SessionStorage` (TS: `S3Storage`) to avoid clashing with `storage::S3Storage`.
- Client construction is a builder (`build().await`), not a constructor: resolving the AWS config is async.
  `client` + `region` together is still an error, as in TS.
- `prefix` goes through `normalize_prefix`, so `..` or `\` in a prefix is an error rather than a literal
  key segment (matches Python's `S3Storage`), and redundant/trailing separators are collapsed: TS keeps
  `prefix` verbatim and emits `${prefix}/…`, so TS with `prefix: "a/"` writes `a//sess/…` and reports
  `_prefix === "a"` where Rust writes `a/sess/…` and `prefix()` returns `"a/"`.
- No `us-east-1` fallback: TS session storage does `new S3Client({ region: config.region ?? 'us-east-1' })`,
  while Rust leaves region resolution to the AWS default chain (as the unified TS backend and `BedrockModel`
  do), so an unconfigured environment errors instead of silently using `us-east-1`.
- A missing *bucket* is an error in `storage::S3Storage::read` (TS unified storage propagates it) but reads
  as "no snapshots" in `S3SessionStorage::list_snapshot_ids` (TS session storage catches it). The two error
  predicates share `is_missing_object_code`.
- TS `S3Storage` (session) is `@deprecated` in favour of the unified `Storage`; the Rust port carries no
  deprecation attribute.
