# Phase 0 review: setup and guardrails

Three independent reviewers (correctness, API, parity) reviewed the diff from the spec commit `7296caba7` to the end of Phase 0. Every finding below was verified before it was fixed. After the fixes, the full gates pass: fmt, clippy with all features and with no default features, tests both ways, docs, MSRV 1.96.0 and `cargo deny`. Each provider feature also passes clippy on its own, for both `strands` and `strands-harness`. The CI workflows were checked with actionlint but have not run on GitHub yet.

Ids: C = correctness, A = API, P = parity.

| finding | disposition | commit |
|---|---|---|
| C1. The `clippy.toml` `allow-*-in-tests` settings cover only `#[test]` functions and `#[cfg(test)]` modules, so shared helpers under `tests/` are still denied `unwrap`, `expect` and `panic`, and `AGENTS.md` says tests may use them | Fixed. Reproduced with a probe crate. `AGENTS.md` and `docs/TESTING.md` now require `tests/main.rs` to start with a crate-level `#![allow(clippy::unwrap_used, clippy::expect_used, clippy::panic, clippy::indexing_slicing, reason = "test code")]`. No integration-test crate exists yet, so there is no file to change today | `13a6a3155` |
