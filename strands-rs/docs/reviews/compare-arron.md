## Notes on the "special attention" items

- **`&mut self` vs handle.** Arron's slice has no hooks, plugins, cancellation, or `ToolContext.agent`. The moment any of those land, `&mut self` + `pub messages` is unimplementable without `unsafe` or `Rc<RefCell>`: TS gives hook callbacks and tools the live agent during `invoke`. The handle is the right call; the only ergonomic loss is `agent.messages` → `agent.messages()` (clone) / `with_messages`.
- **`#[tool]` macro.** Worth adopting as an optional feature — but Arron's codegen infers JSON Schema by matching the type *name string*, so `Option<Vec<String>>`, user enums, nested structs all degrade to `"object"`; it also skips any param named `context`/`agent` by name only. Re-implement on top of `schemars` (generate an input struct deriving `Deserialize + JsonSchema`, call `FunctionTool::builder(..).typed_handler(..)`). The generated `impl` needs nothing new from our `Tool` trait; `wrap_in_tool_result` is already public. Must resolve the `strands_agents::tool` fn-vs-macro name clash first.
- **`Result<Value>` + executor wrapping vs `Result<ToolResultBlock>`.** TS's `Tool.stream` returns `ToolResultBlock`; `_wrapInToolResult` lives in `FunctionTool`. Ours matches; Arron's moves the wrapping to the executor and loses error-status-with-content, multi-block, media, and MCP passthrough. Implementer convenience is served by `typed_handler` returning `Result<impl Serialize>`.
- **`prelude`.** Cheap, conventional (tokio/rayon/bevy), and gives the macro a stable import path. Add.
- **Infallible `build()`.** No — library panics on misconfiguration are the thing Rust API guidelines tell you not to do, and build already has fallible steps (retry-strategy options validation, plugin init). The TS-parity path, if sync construction matters, is deferring `initialize()` to first invoke; `build()` would still return `Result`.

## Changes to make to ours (ranked)

1. **Add `pub mod prelude`** in `lib.rs`: `Agent, AgentBuilder, AgentResult, Error, Result, Model, Tool, ToolContext, FunctionTool, ContentBlock, Message, Role, StopReason` (+ `tool` macro under `macros`).
2. **Rename root re-export `tools::tool` fn** (→ `function_tool(name)` or drop the root re-export; keep `FunctionTool::builder`) to free the `tool` name for the attribute macro.
3. **Add `strands-agents-macros` crate behind `macros` feature**, `#[tool]` on a (async) fn → `fn get_weather() -> FunctionTool` built via a generated `#[derive(Deserialize, JsonSchema)]` input struct + `typed_handler`; description from doc comment; `ctx: ToolContext` param detected by type, not name. Add `#[doc(hidden)] pub mod reexport { async_trait, serde_json, schemars }`.
4. **`BedrockModel::default_model().await -> Result<Self>`** and **`BedrockModel::with_model_id(impl Into<String>).await -> Result<Self>`** (`models/bedrock/mod.rs`), alongside the existing `new(config)`/`builder()`.
5. **`AgentResult::text(&self) -> String`** (delegates to `last_message.text()`); make `Display` plain text (TS `toString()` parity), leave structured output to `structured_output`/`to_json()`.
6. **`pub type ModelEventStream<'a> = BoxStream<'a, Result<ModelStreamEvent>>;`** in `models/model.rs`; use it in `Model::stream`.
7. **Provided `Model::aggregate(&self, &[Message], &StreamOptions) -> Result<StreamAggregatedResult>`** folding `stream_aggregated` to its final item (Arron's shape; for tests/non-streaming callers).
8. **`Error::model_with_source(msg, impl std::error::Error + Send + Sync + 'static)`** constructor in `error.rs` for provider authors.
9. **Builder missing-model error text** → "Agent requires a model; call .model(...) before .build()" (`agent/builder.rs` `NO_MODEL_MESSAGE`).
10. **Ensure `StreamOptions`/`StreamAggregatedResult` are `#[non_exhaustive]` + `Default`** so struct-literal construction with `..Default::default()` is the documented pattern for provider impls.
11. **Docs**: add "Adding a model provider" and "Known deviations from a literal port" sections (from Arron's AGENTS.md / PORTING.md) to our AGENTS.md / DESIGN.md.
12. **Example parity**: ship `examples/weather_agent.rs` equal to Arron's 14-line form once 3 + 4 land — the readability benchmark.

## Things Arron's slice would need from ours

- `Agent` as a `Clone` handle with `&self` invoke — prerequisite for hooks (`HookRegistry`, events), plugins (`Plugin::init_agent`), `ToolContext.agent`, cancellation, concurrent-invocation guard.
- `Tool::invoke -> Result<ToolResultBlock>` + `FunctionTool::wrap_in_tool_result` (TS `_wrapInToolResult` parity incl. content-block passthrough) and `ToolExecutor` trait (sequential/concurrent).
- `InvokeInput`, `InvokeOptions`/`Limits`, `agent.stream()` (`AgentStream`/`AgentStreamEvent`), `structured_output<T>`.
- `Model::stream_aggregated` as a stream of `AggregatedItem` (needed for agent-level streaming), `count_tokens`, `context_window_limit`, `StreamOptions.{cancel, dynamic_trailing_blocks, agent_metadata}`.
- Full `Error` variant set (`Cancelled`, `ConcurrentInvocation`, `Session`, `Storage`, `Plugin`, `JsonValidation`, `ProviderTokenCount`, `DefaultNotConfigured`), `ContentBlock::{GuardContent, Audio, Citations}`, full `StopReason` set, `Message.tracking_id` `#[serde(default)]` (his deserialization rejects TS messages without `trackingId`).
- Conversation managers, session manager + `SnapshotStorage`, retry strategy, Bedrock cache/guardrail config, `schemars`-backed `typed_handler` + `jsonschema` input validation.
- Fallible `build()` instead of panicking `build()`; `tool()` that doesn't swallow registry errors.
